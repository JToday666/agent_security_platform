# 国际化架构说明

本文档说明前端国际化能力的目录边界、接入策略和后续改造方向。跨端国际化边界、当前状态和剩余缺口见 `share/i18n方案.md`。

## 1. 职责边界

前端负责浏览器体验层国际化：

- 页面标题、导航、按钮、表单、筛选、排序、状态、空态、错误态、弹窗和 Toast。
- ECharts 标题、图例、tooltip、series name、坐标轴 label 和空数据状态。
- 日期、时间、数字、百分比、持续时长和相对时间格式化。
- 语言切换体验、`html lang`、组件库 locale、前端缓存 locale 维度和伪本地化。

前端不保存官方业务内容的完整翻译副本。数据集名称、风险分类、报告展示字段和后端业务错误兜底由后端按 `contentLocale` 返回，前端只负责展示、fallback 和必要的 UI 语境化渲染。

## 2. 当前目录

国际化基础设施收口在应用层：

```text
src/app/i18n/
├── intl-format.ts
├── index.ts
├── localeStore.ts
└── messages/
    ├── zh-cn/
    │   ├── common.json
    │   ├── layout.json
    │   ├── auth.json
    │   └── ...
    ├── en-us/
    ├── fr-fr/
    ├── es-es/
    └── ja-jp/
```

`index.ts` 维护支持语言、URL locale 规范化、语言包懒加载、`vue-i18n` 实例和语言激活副作用。`localeStore.ts` 保存 `displayLocale` 与 `contentLocale`。`intl-format.ts` 提供浏览器侧数字和日期格式化。

`messages/` 按 locale 和 domain 拆分，覆盖当前主要页面、共享 UI、表单校验、网络错误、评测报告和图表文案。数据集官方正文、风险分类和后端业务错误兜底仍由后端按 `contentLocale` 返回；前端 mock/reference 内容只服务本地演示分支，不作为官方业务翻译源。

## 3. 语言上下文

前端主要消费两类语言上下文：

| 上下文          | 含义                 | 前端职责                                                     |
| --------------- | -------------------- | ------------------------------------------------------------ |
| `displayLocale` | 当前界面语言         | 驱动 UI 文案、图表文案、格式化、组件库 locale 和 `html lang` |
| `contentLocale` | API 业务展示内容语言 | 通过请求头传给后端，并用于隔离前端业务数据缓存               |

`displayLocale` 应由 URL 承载，路由形态为 `/{locale}/...`。`contentLocale` 通过 `X-App-Locale` 和 `Accept-Language` 传给后端。两者通常同值，但职责不同：前者控制浏览器体验，后者控制后端业务展示字段。

## 4. 路由策略

真实页面路由只维护 `/:locale/...` 体系：

```text
/:locale/
/:locale/dataset
/:locale/dataset/:datasetId
/:locale/leaderboard
/:locale/contact
/:locale/user
/:locale/user/evaluation/:evaluationId
/:locale/user/agents
/:locale/user/agents/register
/:locale/user/agents/:agentId
/:locale/user/submit
/:locale/user/profile
/:locale/:pathMatch(.*)*
```

缺少 locale 的任意入口不维护单独页面组件，而是由通用规则补全首选语言：

```text
/dataset/A1 -> /{preferredLocale}/dataset/A1
/user/agents -> /{preferredLocale}/user/agents
/unknown -> /{preferredLocale}/unknown
```

locale 大小写和别名在进入页面前规范化，例如 `/en-us/dataset` 重定向到 `/en-US/dataset`，`/fr/dataset` 重定向到 `/fr-FR/dataset`，不支持的 `/de-DE/dataset` 重定向到 `/zh-CN/dataset`。

守卫顺序固定为：解析/规范化 locale -> 同步 `RouteLocation.currentLocale` -> 加载语言包 -> 同步 `vue-i18n`、Pinia、API header、`html lang` -> 鉴权。

`RouteLocation.currentLocale` 必须早于 `activateLocale` 同步。语言切换会触发页面文案重渲染，如果命名路由 helper 仍保留旧 locale，页面按钮和导航项可能生成旧语言路径，导致后续点击跳回切换前的语言。

页面内语言切换由顶部导航的 `LanguageSwitcher` 承载。桌面端入口位于“探索 / 工作台”次级入口右侧、用户入口左侧；移动端入口位于导航抽屉内。切换器只替换 URL 第一段 locale，并保留当前路径、query 和 hash，后续状态同步仍交给路由守卫和 `activateLocale`。

## 5. 后续维护重点

前端维护国际化能力时按以下原则推进：

1. 新增或修改用户可见文案时，先进入对应 domain 的 `messages/`，再由组件通过 `t()` 使用。
2. ECharts option 生成继续接收当前 translator，避免图表实例保留旧语言文案。
3. 持续维护硬编码扫描、缺失 key、占位符一致性和术语检查。
4. 与后端 `contentLocale`、业务错误和官方元数据翻译表保持对齐。

每个阶段都应保持页面可用，不允许页面先渲染 key 原文再异步替换文案。

## 6. 资源组织规范

语言包按业务域组织，当前顶层命名空间：

```text
common
layout
auth
public
dataset
agent
submission
evaluation
leaderboard
charts
errors
validation
network
```

key 必须带上下文，例如：

```text
dataset.catalog.title
evaluation.status.running
leaderboard.table.rank
charts.riskDistribution.title
```

禁止无语义 key、字符串拼接和跨语境过度复用。含变量、数量、时间、状态和分数的文案必须使用完整 message 模板。

## 7. 验证重点

前端国际化改造的最小验收重点：

- 切换语言无 key 裸露、无中文闪烁、无旧语言残留。
- `html lang`、组件库 locale、ECharts 文案和 API Header 同步。
- 依赖后端业务展示内容的缓存按 locale 隔离。
- 法语、西语长文本不破坏布局，日语字形和断行可接受。
- IME 输入阶段不误触发截断、校验或提交。
- 用户可见文案不在生产 Vue/TS 中硬编码。

横向导航、Tabs、按钮组和表格列头必须具备明确的文本韧性策略：优先折叠次级入口或允许容器内省略，必要时提供完整 `aria-label` / `title`。禁止依赖无限缩小字号、负字距或语言专属 CSS 避免溢出；`flex` / `grid` 子项必须显式考虑 `min-width: 0`。
