## 2. evaluation-api 门面层

`src/modules/evaluation/api/evaluation-api.ts` 不直接做复杂逻辑，而是做统一分流。

它对页面暴露的接口包括：

- `getSubmitMeta()`
- `precheckAgent(payload)`
- `submitAgent(payload)`
- `getEvaluationRecords()`
- `getEvaluationDetail(evaluationId)`
- `getEvaluationReport(evaluationId)`
- `downloadEvaluationSampleDetails(sampleDetailsUrl)`
- `postEvaluationAction(evaluationId, action)`

分流规则：

- `getEvaluationRecords()`、`getEvaluationDetail()`、`getEvaluationReport()` 在 `ApiConfig.enableApiMock = true` 时走 Mock 实现
- 提交元数据、预检查、正式提交、任务动作和样本下载始终走真实后端实现

这样页面和大部分 composable 不需要关心当前底层到底来自真实后端还是本地模拟。

## 3. 真实后端链路

`src/modules/evaluation/api/internal/live-evaluation-api.ts` 是真实接口的具体实现。

### 3.1 `getLiveSubmitMeta()`

- 请求 `/api/v1/evaluations/meta`
- 调用 `adaptSubmitMeta()`
- 使用 `withMemoryCache()` 缓存元数据

### 3.2 `precheckLiveAgent(payload)` / `submitLiveAgent(payload)`

- 调用前会先把前端提交结构通过 `buildSubmitAgentApiPayload()` 转成后端协议结构
- `precheck` 请求 `/api/v1/evaluations/validate`
- `submit` 请求 `/api/v1/evaluations`

### 3.3 记录与详情

- `getLiveEvaluationRecords()` 请求 `/evaluations`
- `getLiveEvaluationDetail(evaluationId)` 请求 `/evaluations/:id`
- `getLiveEvaluationReport(evaluationId)` 请求 `/evaluations/:id/report`
- `downloadLiveEvaluationSampleDetails(sampleDetailsUrl)` 请求报告 payload 返回的样本明细导出入口
- `postLiveEvaluationAction()` 请求 `/evaluations/:id/actions`

其中，记录、详情、报告、动作以及评分/重算已经和当前后端实现对齐；样本导出依赖报告 payload 是否返回下载入口。

返回结果会经过两步处理：

1. `adaptEvaluationRecord()` / `adaptEvaluationDetail()` / `adaptEvaluationReportPayload()`
2. `sanitizeEvaluationRecord()` / `sanitizeEvaluationDetail()`

第一步负责字段适配，第二步负责前端展示语义收敛。

## 4. Mock 链路

Mock 评测读取由 `mock-evaluation-api.ts` 提供，数据来自 `mock/evaluation-fixtures.ts`。报告 Mock 由 `buildMockReportPayload()` 从记录派生；记录页趋势直接由当前记录列表在前端构建。

## 5. 记录列表页

`src/modules/evaluation/pages/EvaluationRecordsPage.vue` 的逻辑相对直接：

1. `onMounted()` 时调用 `loadRecords()`
2. 通过 `getEvaluationRecords()` 拉取记录
3. 把结果交给 `filterEvaluationRecords()` 做搜索和筛选
4. 用 `EvaluationRecordItem.vue` 渲染列表

页面当前保留的头部信息只有：

- 页面标题
- 页面说明
- “提交评测”动作按钮

不再在 Hero 区展示任务统计 chip。

记录页的趋势分析区由 `EvaluationTrendPanel.vue` 驱动：

1. 进入页面后读取评测记录
2. `EvaluationTrendPanel.vue` 根据记录列表构建最近 10 次 / 全部评测趋势
3. 能力视图 / 风险视图切换只切换图表指标，不重新请求
4. 图例来自当前视图指标，折线名称与图例保持一致
5. 单个指标缺失时对应点写入空值，其它折线继续展示

## 6. 详情页与轮询

`src/modules/evaluation/composables/useEvaluationDetailPage.ts` 是详情页的核心。

### 6.1 `loadDetail(silent)`

职责：

- 读取当前评测详情
- 静默刷新时避免重置整个页面加载态
- 成功后调用 `syncPolling()` 决定是否继续轮询

### 6.2 `syncPolling()`

轮询周期当前固定为 10 秒。

是否需要继续轮询由 `shouldPollEvaluation(status)` 决定。该规则定义在 `lib/evaluation-status.ts`：

- `paused` 不轮询
- 终态 `completed / terminated / canceled / failed` 不轮询
- 其余中间状态继续轮询

### 6.3 任务动作

`openActionDialog(action)` 会根据动作类型生成：

- 标题
- 提示文案
- danger 标记
- 确认按钮文本

`confirmAction()` 最终调用 `runAction(action)` 发送请求。

### 6.4 冲突回正

当任务动作返回特定冲突码（如 `40901`、`40902`）时：

- 页面会保留错误消息
- 但会再补拉一次最新详情

这样可以让前端状态尽快回到服务端当前真实状态，而不是停留在用户操作前的旧状态。

## 7. 状态展示规则

`src/modules/evaluation/lib/evaluation-status.ts` 统一收口：

- `getEvaluationStatusLabel()`
  把状态码映射为中文标签
- `getEvaluationStatusTone()`
  为标签选择色调
- `shouldPollEvaluation()`
  定义轮询条件
- `formatEvaluationScore()`
  定义分数展示方式

动作可用性则收口在 `model/evaluation-controls.ts`。

## 8. 详情页与报告视图分离架构

评测详情页遵循“结论、解释、证据、下载”四层结构，由两个核心接口驱动：

- `GET /api/v1/evaluations/{evaluationId}`：提供基础信息、状态、进度和任务级报告摘要。
- `GET /api/v1/evaluations/{evaluationId}/report`：提供前端完整报告数据；详情页在 `finalReportAvailable` 为真时直接请求它，返回 404 / 40400 时降级为空态。

详情接口先行渲染顶部结论带、样本统计和基础信息。`EvaluationDetailPage.vue` 只保留页面壳、状态分支和弹窗；`evaluation-detail-view.ts` 派生摘要项、样本分段、样本统计和基础信息分组。

报告接口失败、不可用或返回空数据时，只影响报告区；状态、基础信息、样本统计和代表样本仍可阅读。

报告视图按职责分为四个入口：

- `evaluation-report-metrics.ts`
  能力结构行、结果率行、置信区间摘要和指标标签。
- `evaluation-report-insights.ts`
  报告概览、难度桶说明、数据集结果说明和趋势摘要。
- `evaluation-report-chart-options.ts`
  雷达图、置信区间条、环形图、结果率图、难度桶组合图、数据集堆叠图、样本散点图和趋势折线图 option。
- `evaluation-report-samples.ts`
  代表样本选择。

报告视图派生内容包括：

1. 能力结构行：输出雷达图对应的“指标 / 分数 / 解释”三列。
2. 摘要指标：输出综合分、安全识别、风险率和置信区间。
3. 结果率行：输出完成率、成功率和条件成功率。
4. 图表 option：输出雷达图、置信区间条、环形图、结果率图、难度桶组合图、数据集横向堆叠图和样本散点图配置。
5. 趋势 option：输出图例、横轴、tooltip 和当前视图折线。
6. 代表样本选择：优先展示成功样本，再展示失败或异常样本。

报告区按阅读顺序组织：

1. 能力结构：左侧为 6 维指标表，右侧为同维度雷达图；安全稳定由 `100 - unsafeRate` 派生。
2. 置信区间：用 `psQ05 / psQ50 / psQ95` 展示分数波动范围。
3. 样本结果：三态环形图解释成功、失败、异常数量结构，结果率图解释完成率、成功率和条件成功率。
4. 难度表现：堆叠柱展示成功、失败、异常数量，折线展示各难度桶成功率。
5. 风险类型：横向堆叠条按数据集展示成功、失败、异常数量，适配长数据集名称。
6. 样本定位：难度-耗时散点图用结果颜色区分成功、失败和异常样本。

难度桶说明默认选择成功率最低的区间，悬停柱状图时预览对应区间，点击后锁定该区间。说明文本展示所选区间的成功率、成功数、失败数和异常数。

数据集结果说明默认选择失败和异常总数最高的数据集，悬停堆叠柱时预览对应数据集，点击后锁定该数据集。说明文本展示所选数据集的成功数、失败数和异常数。

样本明细下载由详情页证据区触发。下载接口失败时，页面保留证据区和报告区内容，并在下载入口附近显示局部失败提示。
