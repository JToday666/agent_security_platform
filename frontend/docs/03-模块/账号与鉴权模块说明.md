# 账号与鉴权模块说明

本文档说明 `src/modules/account/` 的页面、组件、Store 和关键鉴权逻辑。

## 1. 模块文件概览

### 1.1 页面与组件

| 文件                         | 类型  | 职责                                                               |
| ---------------------------- | ----- | ------------------------------------------------------------------ |
| `components/LoginDialog.vue` | 组件  | 全局登录 / 注册弹窗，负责表单切换、基础校验、提交、登录后跳转      |
| `pages/ProfilePage.vue`      | 页面  | 个人资料页，负责资料展示、头像上传、用户名 / 密码更新              |
| `stores/userStore.ts`        | Store | 统一维护 token、当前用户、登录恢复、资料更新、头像版本与登录后回跳 |

### 1.2 依赖的共享能力

- `src/shared/api/http-client.ts`
- `src/shared/api/api-runtime.ts`
- `src/shared/lib/asset-display-url.ts`
- `src/shared/constants/storage-keys.ts`

## 2. UserStore 的状态与职责

`src/modules/account/stores/userStore.ts` 是前端鉴权链的核心。

### 2.1 关键状态

- `showLogin`
  当前是否显示登录弹窗
- `token`
  当前登录 token，初始化时从 `localStorage` 恢复
- `currentUser`
  当前用户资料
- `avatarVersion`
  头像 cache bust 版本号，用于头像更新后强制刷新展示 URL
- `postLoginRedirect`
  登录后回跳目标，从 `sessionStorage` 读取并维护

### 2.2 关键计算属性

- `isLogin`
  只有 token 与 currentUser 同时存在才视为已登录
- `avatarDisplayUrl`
  基于 `appendCacheBustParam()` 生成带版本号的头像地址

### 2.3 关键方法

- `restoreLogin()`
  启动时恢复登录态；先恢复 token，再请求 `/auth/me` 拉用户信息
- `login(identifier, password)`
  调 `/auth/login`，成功后写入 token 与用户
- `register(userData)`
  调 `/auth/register`，成功后同样写入 token 与用户
- `logout()`
  清除本地鉴权状态
- `openLoginDialog()`
  打开全局登录弹窗
- `setPostLoginRedirect(path)` / `consumePostLoginRedirect()`
  维护登录后回跳地址
- `fetchProfile()` / `updateProfile()`
  读写个人资料
- `uploadAvatar(file)`
  上传头像，并同步更新当前用户头像地址与版本号

## 3. LoginDialog 逻辑

`src/modules/account/components/LoginDialog.vue` 是全局弹窗，不属于某个页面的局部子树。

### 3.1 它负责的事

- 在登录 / 注册模式之间切换
- 承担基本前端校验
  用户名长度、邮箱格式、密码长度、确认密码一致性
- 调用 `userStore.login()` 或 `userStore.register()`
- 成功后消费 `postLoginRedirect`
  如果有原始目标页则跳回目标页，否则回到 `RouteLocation.userCenter`

### 3.2 它不负责的事

- 不负责全局未授权判断
  这由 `main.ts + http-client.ts` 完成
- 不负责业务页面里的具体提交逻辑
  页面只负责在需要时调用 `userStore.openLoginDialog()`

## 4. ProfilePage 逻辑

`src/modules/account/pages/ProfilePage.vue` 是资料页，逻辑重点有三块。

### 4.1 页面初始化

- 优先读 `currentUser`
- 若当前没有用户对象，则调用 `userStore.fetchProfile()`
- 把当前资料同步到本地表单

### 4.2 头像上传

头像上传链路包含：

- 文件类型限制：仅 JPG / PNG
- 文件大小限制：不超过 2MB
- 本地预览：通过 `FileReader` 先生成预览图
- 真实上传：调用 `userStore.uploadAvatar(file)`
- 成功后：清除预览，刷新头像展示 URL

这里的关键点不是组件自己拼接头像地址，而是交给 Store 里的 `avatarDisplayUrl` 统一处理。

### 4.3 资料更新

提交前会检查：

- 用户名长度至少 3 位
- 新密码长度至少 6 位
- 两次密码一致

只有真正有变更时才会调用 `userStore.updateProfile()`。没有变更会直接提示。

## 5. 鉴权链在前端中的位置

账号模块不是独立闭环，而是前端整体运行链的一部分。

完整协作关系如下：

1. 页面或路由守卫发现需要登录
2. 调用 `userStore.openLoginDialog()`
3. 登录弹窗完成认证后写入 Store
4. 若之前记录过 `postLoginRedirect`，则登录成功后跳回原目标页
5. 如果后续任意真实 API 返回 401，则由 `http-client.ts` 派发全局 `unauthorized` 事件
6. `main.ts` 统一清理状态并重新唤起登录

这个设计让鉴权逻辑集中在三处：

- `userStore.ts`
- `LoginDialog.vue`
- `main.ts / route-guards.ts / http-client.ts`
