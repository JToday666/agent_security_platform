# 提交评测模块说明

本文档说明 `src/modules/submission/` 如何编排提交页、维护草稿、加载目录、选择 API Agent、校验参数并创建评测任务。

## 2. 提交页初始化

`useSubmitAgentPage.ts` 在 `onMounted()` 中调用 `initializePage()`：

1. 并行读取 `getSubmitMeta()` 和 `getAgents({ includeArchived: false })`
2. 用元数据初始化或修正 `submitDraftStore.form`
3. 通过 `normalizeSubmitDraftParameters()` 归一化难度、超时时间和最大步数
4. 加载攻击场景库并清洗当前评测项选择
5. 从 URL query 应用 `attackScenarioId` 和 `evaluationItemIds`
6. 从 URL query 应用 `agentId`，或默认选择第一个 `active` 且 `canSubmitEvaluation=true` 的 Agent

## 3. API Agent 提交

API 模式只提交已注册、状态为 `active` 且 `canSubmitEvaluation=true` 的 Agent。

提交 payload 由 `buildSubmitPayloadSnapshot()` 先收敛为稳定快照，再由 `buildSubmitPayloadFromSnapshot()` 生成真实提交结构。

提交给前端校验与 API 的结构为：

```json
{
  "requestId": "submit_xxx",
  "submitMethod": "api",
  "agentId": "agt_001",
  "attackScenarioId": "prompt_injection",
  "evaluationItemIds": ["A1_identity_leakage"],
  "parameters": {
    "difficulty": 0.5,
    "timeoutMinutes": 20,
    "maxSteps": 30
  },
  "leaderboardDisplayMode": "public"
}
```

界面仍保留 Docker 入口，但当前为禁用态，真实提交始终走 API。

`leaderboardDisplayMode` 用于控制榜单展示身份：

| 值        | 含义                           |
| --------- | ------------------------------ |
| public    | 进入排行榜，展示智能体公开名称 |
| anonymous | 进入排行榜，只展示匿名身份     |

新提交不再提供“不进榜”选项。历史记录中的旧 `publicToLeaderboard=false` 只在评测记录与详情中展示为“未排行”。

正式提交流程：

1. 本地校验 `validateSubmitPayload(payload, meta, validEvaluationItemIds, activeAgentIds)`
2. 调用 `precheckAgent(payload)`，真实接口为 `POST /evaluations/validate`
3. 展示确认弹窗
4. 调用 `submitAgent(payload)`，真实接口为 `POST /evaluations`
5. 清空草稿并跳转评测详情页

`requestId` 由 `pendingRequest` 和 payload 摘要维护，避免同一请求重复创建不同任务。表单内容变化时，`shouldClearPendingSubmitRequest()` 会清理不再匹配当前 payload 的待提交请求。

## 4. 攻击场景与评测项选择

评测项选择区只使用 `useSubmitAttackScenarioCatalog.ts` 返回的可用攻击场景、风险域和评测项 ID，不在组件内发起额外请求。

组件职责如下：

- `SubmitEvaluationItemPanel.vue`
  维护攻击场景选择、搜索词、筛选后的风险域、已选风险域数量、已选评测项数量、当前结果数量和加载 / 错误 / 空态展示。
- `SubmitRiskDomainList.vue`
  渲染风险域列表，并把风险域、评测项、展开状态事件向上传递。
- `SubmitRiskDomainBlock.vue`
  渲染单个风险域、半选状态、全选状态、展开按钮和评测项复选项。

搜索范围包括风险域名称、风险域说明、评测项名称和评测项摘要。未选择攻击场景前不能选择评测项；切换攻击场景会清空已选评测项、展开状态、query 同步和选择错误提示。批量全选使用当前攻击场景下的全部可用评测项；清空只清除当前草稿中的评测项选择。

## 5. Docker 状态

Docker 入口保留在提交方式中，但当前仅作为禁用选项展示。

当用户选择 Docker：

- Agent 选择区显示“Docker 提交暂不可用”
- `canSubmit` 固定为 `false`
- `handleSubmit()` 不调用 `/evaluations/validate` 或 `/evaluations`

## 6. Mock 行为

Mock 开关仍然只有一个：

```text
VITE_ENABLE_API_MOCK=true
```

提交页当前始终读取真实 Agent 列表，并调用真实评测元数据、预检查和创建接口。`VITE_ENABLE_API_MOCK=true` 只影响评测记录、评测详情、评测报告和排行榜读取，不接管提交链路。
