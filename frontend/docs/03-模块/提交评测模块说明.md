# 提交评测模块说明

本文档说明 `src/modules/submission/` 如何编排提交页、维护草稿、加载目录、选择 API Agent、校验参数并创建评测任务。

## 1. 模块文件概览

| 文件                                        | 职责                                                                           |
| ------------------------------------------- | ------------------------------------------------------------------------------ |
| `pages/SubmitAgentPage.vue`                 | 提交页视图，拼装提交方式、Agent 选择、参数、数据集面板和操作栏                 |
| `composables/useSubmitAgentPage.ts`         | 提交页主编排逻辑，负责初始化、Agent 预选、目录联动、预检查、确认提交和成功跳转 |
| `composables/useSubmitDatasetCatalog.ts`    | 提交页专用目录状态机                                                           |
| `stores/submitDraftStore.ts`                | 提交草稿、展开分类、待提交请求信息、目录同步                                   |
| `components/SubmitMethodSelector.vue`       | API 提交方式展示，Docker 置灰禁用                                              |

## 2. 提交页初始化

`useSubmitAgentPage.ts` 在 `onMounted()` 中调用 `initializePage()`：

1. 并行读取 `getSubmitMeta()` 和 `getAgents({ includeArchived: false })`
2. 用元数据初始化或修正 `submitDraftStore.form`
3. 通过 `normalizeSubmitDraftParameters()` 归一化难度、超时时间和最大步数
4. 加载数据集目录并清洗当前数据集选择
5. 从 URL query 应用 `datasetIds`
6. 从 URL query 应用 `agentId`，或默认选择第一个 `active` Agent

## 3. API Agent 提交

API 模式只提交已注册且状态为 `active` 的 Agent。

提交 payload 由 `buildSubmitPayloadSnapshot()` 先收敛为稳定快照，再由 `buildSubmitPayloadFromSnapshot()` 生成真实提交结构。

提交给前端校验与 API 的结构为：

```json
{
  "requestId": "submit_xxx",
  "submitMethod": "api",
  "agentId": "agt_001",
  "selectedDatasetIds": ["A1_identity_leakage"],
  "parameters": {
    "difficulty": 0.5,
    "timeoutMinutes": 20,
    "maxSteps": 30
  },
  "leaderboardDisplayMode": "public"
}
```

界面仍保留 Docker 入口，但当前为禁用态，真实提交始终走 API。

`leaderboardDisplayMode` 用于控制榜单展示身份：

| 值        | 含义                           |
| --------- | ------------------------------ |
| public    | 进入排行榜，展示智能体公开名称 |
| anonymous | 进入排行榜，只展示匿名身份     |

新提交不再提供“不进榜”选项。历史记录中的旧 `publicToLeaderboard=false` 只在评测记录与详情中展示为“未排行”。

正式提交流程：

1. 本地校验 `validateSubmitPayload(payload, meta, validDatasetIds, activeAgentIds)`
2. 调用 `precheckAgent(payload)`，真实接口为 `POST /evaluations/validate`
3. 展示确认弹窗
4. 调用 `submitAgent(payload)`，真实接口为 `POST /evaluations`
5. 清空草稿并跳转评测详情页

`requestId` 由 `pendingRequest` 和 payload 摘要维护，避免同一请求重复创建不同任务。表单内容变化时，`shouldClearPendingSubmitRequest()` 会清理不再匹配当前 payload 的待提交请求。

## 4. 数据集选择

数据集选择区只使用 `useSubmitDatasetCatalog.ts` 返回的可用分类和数据集 ID，不在组件内发起额外请求。

组件职责如下：

- `SubmitDatasetPanel.vue`
  维护搜索词、筛选后的分类、已选风险域数量、已选数据集数量、当前结果数量和加载 / 错误 / 空态展示。
- `SubmitDatasetCategoryList.vue`
  渲染分类列表，并把分类、数据集、展开状态事件向上传递。
- `SubmitDatasetCategoryBlock.vue`
  渲染单个风险域、半选状态、全选状态、展开按钮和数据集复选项。

搜索范围包括风险域名称、风险域说明、数据集名称和数据集摘要。批量全选使用当前目录中的全部可用数据集；清空只清除当前草稿中的数据集选择。

## 5. Docker 状态

Docker 入口保留在提交方式中，但当前仅作为禁用选项展示。

当用户选择 Docker：

- Agent 选择区显示“Docker 提交暂不可用”
- `canSubmit` 固定为 `false`
- `handleSubmit()` 不调用 `/evaluations/validate` 或 `/evaluations`

## 6. Mock 行为

Mock 开关仍然只有一个：

```text
VITE_ENABLE_API_MOCK=true
```

提交页当前始终读取真实 Agent 列表，并调用真实评测元数据、预检查和创建接口。`VITE_ENABLE_API_MOCK=true` 只影响评测记录、评测详情和评测报告读取，不接管提交链路。
