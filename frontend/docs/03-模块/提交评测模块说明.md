# 提交评测模块说明

本文档说明 `src/modules/submission/` 如何编排提交页、维护草稿、加载目录、校验参数并与评测模块协作。

## 1. 模块文件概览

### 1.1 页面与核心编排

| 文件                                     | 类型       | 职责                                                                         |
| ---------------------------------------- | ---------- | ---------------------------------------------------------------------------- |
| `pages/SubmitAgentPage.vue`              | 页面       | 提交页视图，拼装基础信息、提交方式、参数、数据集面板和操作栏                 |
| `composables/useSubmitAgentPage.ts`      | composable | 提交页主编排逻辑，负责初始化、目录联动、校验、预检查、确认提交、提交成功跳转 |
| `composables/useSubmitDatasetCatalog.ts` | composable | 提交页专用目录状态机，管理 `idle/loading/refreshing/ready/empty/error`       |
| `stores/submitDraftStore.ts`             | Store      | 提交草稿、展开分类、待提交请求信息、目录同步                                 |

### 1.2 组件层

| 文件                                     | 职责                                |
| ---------------------------------------- | ----------------------------------- |
| `components/SubmitBasicInfoForm.vue`     | 基础信息与接入字段                  |
| `components/SubmitMethodSelector.vue`    | API / Docker 提交方式切换           |
| `components/SubmitParameterControls.vue` | 参数编辑                            |
| `components/SubmitDatasetPanel.vue`      | 数据集选择、分类展开、批量选择      |
| `components/SubmitActionBar.vue`         | 提交摘要、错误提示、提交 / 重置按钮 |

### 1.3 模型与工具

| 文件                           | 职责                                           |
| ------------------------------ | ---------------------------------------------- |
| `model/parameter-validator.ts` | 参数归一化、范围校验、URL 校验、requestId 校验 |
| `lib/submit-query-utils.ts`    | 从 URL query 中解析合法 `datasetIds`           |

## 2. 提交页初始化

提交页打开时，`useSubmitAgentPage.ts` 会在 `onMounted()` 中调用 `initializePage()`。

初始化顺序如下：

1. 读取 `getSubmitMeta()`
   获取提交方式、参数范围、默认值等元数据
2. `submitDraftStore.applyMeta(meta)`
   用元数据初始化或修正当前表单
3. 归一化难度与超时时间
4. 调用 `loadCatalog(true)`
   通过 `useSubmitDatasetCatalog()` 拉取数据集目录
5. `submitDraftStore.syncWithCatalog(categories)`
   根据最新目录清洗数据集选择和展开状态
6. `applyDatasetQuerySelection()`
   若 URL 中带了 `datasetIds`，则把合法项应用到当前选择

初始化的目标不是单纯把表单渲染出来，而是让“后端元数据 + 目录 + URL 传参 + 旧草稿”最终收敛成一份可提交状态。

## 3. SubmitDraftStore 的职责

`src/modules/submission/stores/submitDraftStore.ts` 持有提交页的可编辑状态。

### 3.1 关键状态

- `form`
  当前提交表单
- `expandedCategoryIds`
  数据集面板中已展开的分类
- `pendingRequest`
  最近一次待提交请求的 `requestId` 与 `payloadDigest`
- `hasSyncedCatalog`
  当前草稿是否已经与目录同步过

### 3.2 关键方法

- `applyMeta(meta)`
  首次创建默认表单，或在元数据变化时修正已有表单
- `syncWithCatalog(categories)`
  用最新目录清洗已选数据集；首次同步且没有选中项时，会默认选入可用数据集
- `resetDraft(meta, categories)`
  把整张表单重置成默认值，并恢复默认数据集集合
- `setSubmitMethod(method)`
  切换提交方式，并清理不再适用的敏感字段
- `setPendingRequest(value)`
  维护幂等提交所需的待提交请求信息
- `clearDraftAfterSubmit()`
  提交成功后清空草稿

## 4. useSubmitDatasetCatalog 状态机

`src/modules/submission/composables/useSubmitDatasetCatalog.ts` 与数据集模块里的全局目录 Store 不同，它是提交页专用的、局部的目录状态机。

设计目的：

- 让提交页可以精确区分 `loading` 与 `refreshing`
- 独立维护错误态和空态
- 对外直接暴露提交页需要的 `enabledCategories` 与 `datasetIds`

状态含义：

- `idle`
  尚未加载
- `loading`
  首次加载
- `refreshing`
  已有目录基础上的刷新
- `ready`
  已成功加载且有数据
- `empty`
  加载成功但没有可用数据集
- `error`
  加载失败

## 5. 参数归一化与校验

`src/modules/submission/model/parameter-validator.ts` 是提交模块最重要的规则文件之一。

### 5.1 归一化函数

- `normalizeDifficulty(value, meta)`
  把难度限制到范围内，并对齐步长
- `normalizeTimeoutMinutes(value, meta)`
  把超时值限制到范围内，并对齐步长且取整

### 5.2 校验函数

- `isValidHttpUrl(value)`
  校验 API 接入地址是否是有效的 HTTP / HTTPS URL
- `validateSubmitPayload(payload, meta, validDatasetIds)`
  提交前总校验入口

当前校验内容包括：

- 智能体名称是否为空、是否超长
- 提交方式是否在后端允许的列表中
- API 模式下的 `baseUrl` 是否合法
- Docker 模式下的 `imageUri` 是否为空
- 难度和超时是否越界、是否与步长对齐
- 数据集是否为空、是否重复、是否超过上限、是否包含失效 ID
- `requestId` 格式是否合法

## 6. 提交主链路

`useSubmitAgentPage.ts` 里最关键的几个方法如下。

### 6.1 `applyDatasetQuerySelection()`

作用：

- 从 `route.query.datasetIds` 读取数据集 ID
- 调用 `resolveDatasetIdsFromQuery()` 去掉非法值
- 把合法数据集写入当前表单

这使得“数据集详情页 -> 提交页”的链路可以带着上下文进入。

### 6.2 `buildPayload(mode)`

作用：

- 把当前表单收敛成标准 `SubmitAgentPayload`
- 在 `submit` 模式下为 payload 分配稳定 `requestId`
- 结合 `pendingRequest` 实现幂等提交保护

### 6.3 `handleSubmit()`

提交流程：

1. 先检查目录是否就绪
2. 组装 payload
3. 调用 `validateSubmitPayload()`
4. 调用 `precheckAgent(payload)`
5. 根据预检查结果生成确认框文案并打开确认弹窗

### 6.4 `confirmSubmit()`

提交流程：

1. 调用 `submitAgent(confirmedPayload)`
2. 关闭确认框
3. 清空草稿
4. 跳转到 `RouteLocation.evaluationDetail(evaluationId)`

## 7. 提交模块与其他模块的关系

- 从数据集模块接收目录、合法数据集 ID、数据集切换工具
- 从评测模块接收 `submit-meta`、预检查与正式提交接口
- 从账号模块间接受益于登录守卫和登录恢复

因此提交模块是多个业务域的汇合点，也是前端里最典型的“编排型模块”。
