# 国际化收口说明

本文档只保留跨端国际化的当前事实、职责边界和剩余缺口。前端实现细节见 `frontend/docs/02-架构/国际化架构说明.md`，后端入口见 `backend/docs/01-总览/后端模块实现清单.md` 与 `backend/app/platform/i18n/`。

## 1. 支持语言

当前支持语言固定为：

| Locale  | 语言               |
| ------- | ------------------ |
| `zh-CN` | 简体中文，默认语言 |
| `en-US` | US-English         |
| `fr-FR` | 法国法语           |
| `es-ES` | 西班牙西班牙语     |
| `ja-JP` | 日语               |

以下专有名词在所有语言中保留英文：

```text
AEGIS
Agent
API
Docker
Oracle
```

## 2. 已落地范围

### 前端

- URL 使用 `/:locale/...`，无 locale 或别名 locale 会重定向到规范 locale。
- `src/app/i18n/index.ts` 维护支持语言、语言包懒加载、`vue-i18n` 实例、`html lang`、`RouteLocation.currentLocale` 和 API 语言头同步。
- `src/app/i18n/localeStore.ts` 同步保存 `displayLocale` 与 `contentLocale`。
- `src/app/i18n/messages/<locale>/` 按 domain 拆分页面、共享 UI、表单、网络错误、评测报告和图表文案。
- `src/app/i18n/message-catalog.test.ts` 检查 key、占位符、空 domain 和部分术语规则。
- 数据集缓存和页面刷新已按当前 locale 做隔离或刷新。

### 后端

- `LocaleMiddleware` 只读取 `X-App-Locale`，规范化后写入请求级 `ContextVar`。
- 后端 JSON 响应写入 `Content-Language`，并通过 `Vary: X-App-Locale` 声明缓存维度。
- `translate()` / `localize_message()` 支持稳定 message key、参数插值和 `zh-CN` fallback。
- 后端异常处理、统一响应和首批后端生成文案已接入本地化。
- 数据集查询链路会按当前 locale 读取 metadata `translations`，缺失时回退默认中文或稳定字段。

## 3. 职责边界

前端负责浏览器体验层：

- 导航、页面标题、按钮、表单、筛选、排序、状态、空态、错误态、弹窗和 Toast。
- ECharts 标题、图例、tooltip、series name、坐标轴 label 和空数据状态。
- 日期、时间、数字、百分比、持续时长和相对时间格式化。
- 语言切换体验、`html lang`、前端缓存 locale 维度和前端 i18n 质量门禁。

后端负责业务语义层：

- API 错误 message / fallback message。
- 数据集名称、简介、详情、来源、风险分类、风险子类、资产类型和攻击投递类型。
- 排行榜匿名名称、后端 validation 兜底消息和后端生成的报告展示字段。

前端不维护官方数据集、风险分类和报告摘要的完整翻译副本；后端不负责按钮、菜单、浏览器弹窗、组件状态和图表交互文案。

## 4. 不翻译内容

以下内容保持稳定值或原文，不随 UI 语言变化：

```text
接口字段名
数据库字段名
接口路径
enum value
错误 code
ID
日志字段
datasetId / agentId / evaluationId / runId / sampleId
用户填写的 Agent 名称和描述
用户输入内容
文件名
URL
模型名和 provider 名称
任务 payload
网页原始内容
Agent 原始响应
Oracle 原始输出
events.jsonl 原始事件
外部系统原始返回

```

UI 语言不得影响 Oracle、rubric、评分逻辑、结构化判定字段和审计证据。

## 5. 语言流转

```text
URL locale / 语言切换器
-> displayLocale
-> 前端 UI、图表、格式化和命名路由
-> X-App-Locale / Accept-Language
-> contentLocale
-> 后端业务展示字段、错误兜底和 JSON 语言响应头
```

当前后端只信任 `X-App-Locale`。`Accept-Language` 由前端同步发送，但不作为后端直接决策来源。

## 6. 剩余缺口

- 后端 i18n 仍是“运行时和部分业务内容已接入”，不是全业务完成态。
- 历史 `run_reports.summary_json` 中已固化的展示文本仍需兼容，尚未形成完整按当前 locale enrich 的报告服务层。
- 静态报告导出、导出文件名、sheet 名和表头的语言固化仍未实现。
- Agent 模板等部分后端业务内容是否继续纳入后端本地化，需要按接口和页面真实使用范围逐项确认。
- 前端硬编码扫描、伪本地化和布局溢出治理仍以现有测试与人工定向走查为主，尚未形成完整 CI 阻断链。

## 7. 最小验证入口

前端：

```bash
cd frontend
pnpm test -- src/app/i18n/message-catalog.test.ts
pnpm type-check
```

后端：

```bash
cd backend
uv run pytest tests/modules/platform/test_i18n.py tests/modules/platform/test_exception_handlers.py tests/api/test_contracts.py -q
```

如验证命令在默认沙箱中因 `fastapi.testclient.TestClient` 卡住，需要在沙箱外执行；当前已确认这是执行环境的 asyncio 跨线程唤醒限制，不是 i18n 业务逻辑问题。
