# 数据集与提交接口交接文档

## 1. 文档范围

本文档面向后端实现以下前端已接入、但当前默认仍以 mock/provider 方式运行的接口：

- 数据集目录页 `/dataset`
- 数据集详情页 `/dataset/:datasetId`
- 提交智能体页 `/user/submit`
- 用户中心评测记录页 `/user`
- 评测详情页 `/user/evaluation/:evaluationId`

当前前端的默认策略如下：

- `VITE_USE_LIVE_REFERENCE_API=false` 时，`submit-meta`、`datasets/catalog`、`datasets/{datasetId}` 仍使用前端 fixture/mock。
- `VITE_USE_LIVE_SUBMISSION_API=false` 时，`precheck`、`submit`、`evaluations*` 仍使用前端 mock。
- 后端按本文档补齐接口后，只需打开对应环境变量即可逐步切换到真实接口。

本文档优先描述“前端当前真实接入的目标契约”，不是旧 mock 文件里的历史结构。

## 2. 通用约定

### 2.1 Base URL

前端 `request.ts` 以 `VITE_API_BASE_URL` 为基准，建议后端统一挂在：

```text
/api/v1
```

下文展示的路径均为完整路径。

### 2.2 通用响应格式

所有接口统一返回 envelope：

```json
{
  "code": 0,
  "message": "success",
  "data": {}
}
```

错误示例：

```json
{
  "code": 40002,
  "message": "参数超出允许范围。",
  "data": null
}
```

前端实际只依赖以下约定：

- `code === 0` 视为成功
- 非 `0` 视为失败
- 失败时优先展示 `message`
- `data` 在失败时允许为 `null`

### 2.3 鉴权矩阵

| 接口                                     | 是否要求登录 | 说明                 |
| ---------------------------------------- | ------------ | -------------------- |
| `GET /api/v1/agents/submit-meta`         | 否           | 公开的参考元数据     |
| `GET /api/v1/datasets/catalog`           | 否           | 公开目录             |
| `GET /api/v1/datasets/{datasetId}`       | 否           | 公开详情             |
| `POST /api/v1/agents/precheck`           | 是           | 预检查属于提交流程   |
| `POST /api/v1/agents/submit`             | 是           | 创建评测任务         |
| `GET /api/v1/evaluations`                | 是           | 当前用户评测记录     |
| `GET /api/v1/evaluations/{evaluationId}` | 是           | 当前用户某次评测详情 |

401 时前端会弹出登录框并记录目标路由，登录成功后自动回跳。

### 2.4 幂等要求

`POST /api/v1/agents/submit` 必须支持幂等。

当前前端已在请求体中传 `requestId`，语义要求如下：

- 同一用户、同一 `requestId` 的重复提交，应返回同一个 `evaluationId`
- 不应重复创建评测任务
- 若请求体其他关键字段与首次提交不一致，建议返回 `40900`

可选增强：

- 额外支持 `Idempotency-Key` 请求头
- 但前端当前不依赖该请求头

## 3. 参考数据接口

### 3.1 获取提交参数元数据

`GET /api/v1/agents/submit-meta`

#### 用途

- 决定提交页支持哪些提交方式
- 决定难度、超时、布尔参数的默认值、上下限和步长
- 决定前端的软提示阈值

#### 推荐响应结构

前端目标结构是扁平结构：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "supportedMethods": ["api", "docker"],
    "difficulty": {
      "min": 0,
      "max": 1,
      "step": 0.1,
      "default": 0.5
    },
    "timeoutMinutes": {
      "min": 15,
      "max": 30,
      "step": 1,
      "default": 15,
      "recommendedMax": 20
    },
    "retryEnabled": {
      "default": false
    },
    "publicToLeaderboard": {
      "default": true
    }
  }
}
```

#### 字段语义

- `supportedMethods`: 当前前端支持值仅有 `api`、`docker`
- `difficulty`: 攻击难度，范围 `0-1`，步长 `0.1`
- `timeoutMinutes`: 超时时间，范围 `15-30`，步长 `1`
- `timeoutMinutes.recommendedMax`: 前端用于“建议设置在 20 分钟内”的软提示阈值
- `retryEnabled.default`: 默认是否启用失败重试
- `publicToLeaderboard.default`: 默认是否公开到排行榜

#### 兼容性要求

前端当前仍兼容旧结构：

```json
{
  "supportedMethods": ["api", "docker"],
  "parameterMeta": {
    "difficulty": { "...": "..." },
    "timeoutMinutes": { "...": "..." },
    "retryEnabled": { "default": false },
    "publicToLeaderboard": { "default": true }
  }
}
```

但这是兼容层，不是推荐新契约。后端正式实现时请直接返回扁平结构，不要继续使用 `parameterMeta` 包裹层。

### 3.2 获取数据集目录

`GET /api/v1/datasets/catalog`

#### Query 参数

| 参数         | 类型          | 必填 | 说明                                          |
| ------------ | ------------- | ---- | --------------------------------------------- |
| `difficulty` | string/number | 否   | 攻击难度，合法值为 `0.0` 到 `1.0`，步长 `0.1` |

示例：

```text
GET /api/v1/datasets/catalog?difficulty=0.5
```

#### 用途

- 数据集目录页加载完整目录
- 提交页按当前攻击难度加载过滤后的目录
- 提交页通过 `catalogVersion` 判断草稿与目录是否仍兼容

#### 响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "catalogVersion": "2026-04-01T10:00:00Z",
    "categoryCount": 4,
    "subcategoryCount": 8,
    "categories": [
      {
        "categoryId": "confidentiality",
        "name": "机密性",
        "meaning": "防止信息泄露",
        "description": "覆盖身份、密钥、隐私等高敏感信息的泄露风险。",
        "sort": 1,
        "enabled": true,
        "subcategoryCount": 2,
        "subcategories": [
          {
            "datasetId": "A1",
            "name": "身份信息泄露",
            "shortDescription": "测试多轮追问和绕行提示下的身份字段泄露。",
            "sampleCount": 1280,
            "updatedAt": "2026-03-28T12:00:00Z",
            "enabled": true
          }
        ]
      }
    ]
  }
}
```

#### 字段语义

- `catalogVersion`: 目录源数据版本号，不因是否带 `difficulty` 筛选而变化
- `categoryCount`: 当前返回结果中的大类数量
- `subcategoryCount`: 当前返回结果中的数据集数量总和
- `categories[].subcategories`: 当前前端仍沿用历史字段名，实际承载的是“数据集摘要列表”
- `enabled`: 前端当前会展示返回项；若后端返回禁用项，建议业务上已过滤

#### 筛选规则

当不传 `difficulty` 时：

- 返回完整目录

当传入 `difficulty` 时：

- 后端按数据集内部难度区间做包含式筛选，即 `range.min <= difficulty <= range.max`
- 内部难度区间是后端实现细节，不需要在响应中暴露
- 筛选后移除没有任何数据集的大类
- `categoryCount`、`subcategoryCount` 必须按筛选后的结果重算
- 筛空结果时返回成功响应，不返回错误

筛空结果示例：

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "catalogVersion": "2026-04-01T10:00:00Z",
    "categoryCount": 0,
    "subcategoryCount": 0,
    "categories": []
  }
}
```

#### 错误语义

- `difficulty` 非法、越界或不符合步长：`40002`
- 服务异常：`50000`

注意：不建议后端对非法 `difficulty` 偷偷做 clamp 或 round。前端需要知道用户输入是否真实生效。

#### 响应

```json
    "sampleCount": 1280,

      }

  }

```

#### 字段语义

- `category` 是当前数据集所属分类摘要
- `resources[].type` 当前前端支持 `docs`、`download`、`demo`
- `media[].type` 当前前端支持 `image`、`video`
- `media[].coverUrl` 可为 `null`
- `media[].sort` 可选

#### 一致性要求

- `datasetId`、`name`、`shortDescription`、`sampleCount`、`updatedAt` 应与 catalog 中的同一数据集保持一致
- catalog 与 detail 应来自同一份 canonical 数据源，不应分别维护两套不一致数据

#### 错误语义

- 数据集不存在或已下线：`40400`
- 服务异常：`50000`

## 4. 提交与预检查接口

### 4.1 提交前预检查

`POST /api/v1/agents/precheck`

#### 请求体

对后端推荐使用 `datasetIds`。前端内部状态名仍是 `selectedDatasetIds`，但已经在 API adapter 边界完成映射。

```json
{
  "agentName": "安全卫士 v1.0",
  "description": "面向企业场景的多工具安全代理。",
  "submitMethod": "api",
  "api": {
    "baseUrl": "https://example.com/agent/run",
    "token": "sk-xxxx"
  },
  "docker": null,
  "parameters": {
    "difficulty": 0.5,
    "timeoutMinutes": 15,
    "retryEnabled": false
  },
  "publicToLeaderboard": true,
  "datasetIds": ["A1", "B1", "D1"],
  "requestId": "8c5ecb4e-79f9-47eb-84d8-a8aa0d53f27f"
}
```

#### 响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "ok": true,
    "warnings": [
      "该次结果将进入公开排行榜，请确认描述中不包含敏感信息。",
      "当前超时时间高于建议值 20，评测排队与执行耗时可能更长。"
    ]
  }
}
```

#### 语义要求

- 预检查只做校验和提醒，不创建评测任务
- `warnings` 用于非阻断提示，前端会展示在提交按钮上方
- 失败时前端优先展示 `message`

#### 建议校验项

- `agentName` 必填，建议长度 `1-100`
- `description` 选填，建议长度不超过 `500`
- `submitMethod` 必须在 `submit-meta.supportedMethods` 内
- `submitMethod=api` 时，`api.baseUrl` 必填且必须是合法 `http/https` URL
- `submitMethod=docker` 时，`docker.imageUri` 必填
- `parameters.difficulty` 必须满足 `submit-meta.difficulty`
- `parameters.timeoutMinutes` 必须满足 `submit-meta.timeoutMinutes`
- `datasetIds` 至少 1 个，且都必须是当前有效数据集
- `publicToLeaderboard` 必须是布尔值
- `requestId` 必须存在

### 4.2 正式提交

`POST /api/v1/agents/submit`

#### 请求体

与 `POST /api/v1/agents/precheck` 保持一致。

#### 成功响应

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "evaluationId": "eval_1711960000123",
    "status": "pending",
    "createdAt": "2026-04-01T12:00:00Z"
  }
}
```

#### 字段语义

- `evaluationId`: 评测任务唯一标识
- `status`: 当前前端支持 `pending`、`running`、`completed`
- `createdAt`: ISO 8601 时间字符串

#### 幂等语义

- 同一用户 + 同一 `requestId` 的重复提交，返回同一条任务
- 建议在幂等重复时仍返回 `code=0`
- 如果同一 `requestId` 对应不同任务参数，建议返回 `40900`

#### 前端行为

- 成功后清空本地草稿
- 自动跳转到 `/user/evaluation/{evaluationId}`

## 5. 评测记录接口

### 5.1 获取当前用户的评测记录

`GET /api/v1/evaluations`

#### 用途

- 用户中心记录页展示

#### 说明

- 当前前端直接期望得到数组，不支持分页 envelope 内再套分页对象
- 如果后端未来要做分页，请另起版本或先与前端同步调整

#### 响应

```json
{
  "code": 0,
  "message": "success",
  "data": [
    {
      "evaluationId": "eval_20260331_001",
      "agentName": "安全卫士 v1.0",
      "description": "面向企业场景的多工具安全代理。",
      "createdAt": "2026-03-31T10:20:00Z",
      "updatedAt": "2026-03-31T11:05:00Z",
      "status": "completed",
      "publicToLeaderboard": true,
      "datasetIds": ["A1", "B1"],
      "datasetNames": ["身份信息泄露", "指令篡改"],
      "submitMethod": "api",
      "score": 94.6,
      "ownerName": "张三",
      "parameters": {
        "difficulty": 0.6,
        "timeoutMinutes": 15,
        "retryEnabled": false
      }
    }
  ]
}
```

#### 字段语义

- `score` 在任务未完成时可为 `null` 或不返回
- `datasetNames` 是给页面直接展示的人类可读名称列表
- `ownerName` 是当前任务所属用户的展示名

## 6. 字段与兼容性说明

### 6.1 `datasetIds` 与 `selectedDatasetIds`

- 前端页面/store 内部仍使用 `selectedDatasetIds`
- 前端 API adapter 向后端发送的是 `datasetIds`
- 后端正式实现时请直接使用 `datasetIds`，不要把前端内部状态名带进接口契约

### 6.2 `catalogVersion`

- 表示目录源数据版本
- 不因是否携带 `difficulty` 查询参数而变化
- 仅在目录源数据、筛选语义或结构兼容性发生变化时更新

### 6.3 `recommendedMax`

- `timeoutMinutes.recommendedMax` 是软提示，不是硬校验上限
- 前端当前逻辑是：`15-30` 允许提交，但 `> 20` 显示提醒
- 如果后端不返回该字段，前端兼容层会默认按 `20` 处理；但正式实现仍建议显式返回

### 6.4 `submit-meta` 旧结构兼容

- 前端当前兼容旧 `parameterMeta` 结构，仅用于后端过渡期
- 后端新实现应直接输出扁平结构
- 后续若前后端都稳定到新结构，可移除这层兼容逻辑

## 7. 推荐错误码

| code    | 含义                         |
| ------- | ---------------------------- |
| `40001` | API 地址格式错误             |
| `40002` | 参数超出允许范围             |
| `40003` | 未选择任何数据集             |
| `40004` | 数据集不存在、已下线或不可选 |
| `40005` | 提交方式当前不可用           |
| `40100` | 未登录或登录失效             |
| `40300` | 无权查看该资源               |
| `40400` | 资源不存在                   |
| `40900` | 幂等冲突或重复请求参数不一致 |
| `50000` | 服务器内部错误               |

## 8. 与前端持久化相关的边界

前端会持久化以下非敏感字段：

- `submitMethod`
- `agentName`
- `description`
- `api.baseUrl`
- `docker.imageUri`
- `docker.username`
- `parameters`
- `publicToLeaderboard`
- `selectedDatasetIds`
- `expandedCategoryIds`

前端不会持久化：

- `api.token`
- `docker.password`
- 任何后续新增的凭证、密钥、Header 敏感值

因此后端不要假设页面刷新后这些敏感字段仍然存在。

## 9. 当前前端默认参考值

- `supportedMethods`: `["api", "docker"]`
- `difficulty`: `min=0`、`max=1`、`step=0.1`、`default=0.5`
- `timeoutMinutes`: `min=15`、`max=30`、`step=1`、`default=15`、`recommendedMax=20`
- `retryEnabled.default`: `false`
- `publicToLeaderboard.default`: `true`
- `catalogVersion`: `2026-04-01T10:00:00Z`

## 10. 联调建议顺序

1. 先完成 `GET /api/v1/agents/submit-meta`
2. 再完成 `GET /api/v1/datasets/catalog`
3. 再完成 `GET /api/v1/datasets/{datasetId}`
4. 接着完成 `POST /api/v1/agents/precheck`
5. 再完成 `POST /api/v1/agents/submit`
6. 最后补 `GET /api/v1/evaluations` 与 `GET /api/v1/evaluations/{evaluationId}`

如果只想先打通提交页，也至少需要先完成前 4 项。
