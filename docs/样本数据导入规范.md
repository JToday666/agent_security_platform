# 样本数据导入规范

## 1. 说明

本文用于约束下一阶段的数据导入器实现。

优先级遵循：

1. `docs/Agent 安全测试平台设计说明书.md`
2. `docs/附录.md`
3. 本文
4. 参考性资料，例如 `docs/算法分享.md` 中示例 `task.json`

结论：

- 设计说明和附录中的 7 张样本域表是当前导入目标。
- 参考性 `task.json` 只能作为原始样本描述来源，不能直接视为数据库入库契约。

## 2. 当前仓库状态

- 当前仓库已预留 `backend/dataset/` 目录，但目录当前为空。
- 因此，下一阶段导入器需要面向“外部样本目录或后续补充进仓库的样本目录”实现。
- 本阶段不提供真实样本 seed，也不假定仓库内已经存在可直接导入的数据。

## 3. 当前导入目标表

本阶段只允许向以下表导入：

- `dataset_sources`
- `attack_delivery_types`
- `risk_categories`
- `risk_subtypes`
- `asset_types`
- `benchmark_samples`
- `sample_oracles`

不允许提前写入：

- `test_runs`
- `run_samples`
- `sample_executions`
- `execution_artifacts`
- `oracle_results`
- `execution_summaries`
- `run_reports`

## 4. 字典字段映射规则

### 4.1 `dataset_sources`

- 业务唯一键：`code`
- 导入时应优先按 `code` 幂等查找，不按 `name` 查找
- `name` 用于展示，可保留数据集原始人类可读名称

### 4.2 `attack_delivery_types`

- 业务唯一键：`code`
- 原始样本中的攻击投递方式必须先标准化为稳定枚举 code，再入库

### 4.3 `risk_categories`

- 业务唯一键：`code`
- 表示风险大类

### 4.4 `risk_subtypes`

- 业务唯一键：`(category_id, code)`
- 导入时必须先解析大类，再解析小类
- `benchmark_samples` 只存 `risk_subtype_id`，不冗余存风险大类

### 4.5 `asset_types`

- 业务唯一键：`code`
- 可为空；当源数据无法稳定归一时，允许样本级 `asset_type_id` 为空

## 5. `benchmark_samples` 映射规则

### 5.1 主键与唯一键

- 主键：`id`
- 业务唯一键：`(dataset_source_id, sample_id)`
- 导入器必须按业务唯一键实现幂等插入或更新

### 5.2 字段映射

| 目标字段 | 导入规则 |
| --- | --- |
| `dataset_source_id` | 由数据集来源 code 查字典表获得 |
| `sample_id` | 样本在数据集内的稳定编号 |
| `sample_name` | 可选展示名称；无则为空 |
| `resource_path` | 样本根目录相对数据集根的路径 |
| `entry_path` | 样本默认入口相对样本根目录的路径 |
| `user_goal` | 用户目标 |
| `attacker_goal` | 攻击目标，可为空 |
| `attacker_is_user` | 是否同一主体，必须为布尔值 |
| `attack_delivery_type_id` | 由攻击投递方式 code 查字典表获得 |
| `risk_subtype_id` | 由风险大类 + 风险小类查字典表获得 |
| `risk_level` | 固定数值 1/2/3 |
| `attack_level` | 固定数值 1/2/3 |
| `asset_type_id` | 由资产类型 code 查字典表获得，可为空 |
| `expected_safe_behavior` | 预期安全行为 |
| `is_active` | 默认 `true`，除非导入清单显式关闭 |

### 5.3 当前不入库的参考字段

以下字段若只出现在参考性 `task.json` 中，不直接进入当前 schema：

- `attacker_source`

处理原则：

- 导入器不得私自扩展当前表结构。
- 若后续确认该字段需要长期保存，再通过新一轮 schema 变更补充。

## 6. `sample_oracles` 映射规则

### 6.1 基础规则

- 一个样本可有多条 oracle
- `oracle_kind` 固定为：
  - `1 = success`
  - `2 = harm`
- 同一样本内，`seq_no` 从 `1` 开始递增，保留原始顺序
- 幂等唯一键：`(sample_id_ref, oracle_kind, seq_no)`

### 6.2 导入字段要求

每条 oracle 入库前必须具备：

- `display_text`
- `evaluator_type`
- `evaluator_config`

### 6.3 与参考性 `task.json` 的关系

若原始样本仅提供：

- `success_oracle: [string, ...]`
- `harm_oracle: [string, ...]`

则这些数组只能视为原始描述，不能直接当作最终数据库对象。

导入前必须先经过一层归一化，补齐：

- `oracle_kind`
- `seq_no`
- `display_text`
- `evaluator_type`
- `evaluator_config`

当前阶段的推荐做法：

- `display_text` 保留原始 oracle 文本
- `evaluator_type` 和 `evaluator_config` 由后续导入器根据正式数据源或适配规则补齐

也就是说，参考性 `task.json` 可作为输入来源，但不是数据库层的直接写入格式。

## 7. code 标准化规则

所有字典表 `code` 字段统一按以下规则标准化：

- 仅使用小写字母、数字和下划线
- 连字符、空格、斜杠统一转为下划线
- 连续分隔符折叠为单个下划线
- 去除首尾下划线
- 名称展示字段 `name` 保留原始人类可读文本

示例：

- `VPI-bench` -> `vpi_bench`
- `Browser-art` -> `browser_art`
- `Local File Modification` -> `local_file_modification`

## 8. `entry_path` 回退解析规则

导入器解析 `entry_path` 时按以下优先级执行：

1. 若正式导入清单显式提供入口路径，则直接使用
2. 若原始样本元数据中存在相对入口路径，则标准化后使用
3. 若样本根目录下存在唯一的 `index.html`，使用 `index.html`
4. 若样本根目录下不存在唯一入口，则导入失败，要求显式补充入口定义

约束：

- `entry_path` 必须是相对样本根目录的相对路径
- 不允许写绝对路径
- 不允许提前写运行态 `entry_url`

## 9. 导入失败规则

出现以下情况时，导入器应拒绝写入该样本并输出明确错误：

- 缺失 `sample_id`
- 缺失 `resource_path`
- 无法确定 `entry_path`
- 无法归一化 `dataset_source` / `attack_delivery` / 风险分类 code
- `risk_level` 或 `attack_level` 不在 `1/2/3`
- oracle 无法补齐为正式数据库对象

## 10. 实现边界

下一阶段导入器只负责：

- 扫描样本源
- 标准化字典值
- 写入 7 张样本域表
- 输出导入结果和错误报告

下一阶段导入器不负责：

- 创建 run
- 启动环境
- 调用 Agent
- 生成报告
