# 后端架构说明

本文档说明 `backend/` 当前已经落地的后端结构、核心分层和公共约束。公开接口的实际行为以代码、测试和烟测脚本为准，不以旧规划口径为准。

## 1. 运行入口

- 应用入口：`app/main.py`
- API 根路由注册：`app/api/router.py`
- v1 路由注册：`app/api/v1/api.py`
- 请求级 DB Session：`app/platform/auth.py`
- 当前用户依赖：`app/modules/auth/dependencies.py`
- 统一响应与异常：`app/platform/http.py`、`app/platform/errors.py`、`app/platform/exception_handlers.py`
- 请求语言上下文与翻译入口：`app/platform/i18n/`
- worker 入口：`app/worker/main.py`
- runtime 执行链路：`app/worker/runtime/`

当前公开 API 路由前缀为 `/api/v1`。

## 2. 分层结构

| 目录                  | 职责                                                     |
| --------------------- | -------------------------------------------------------- |
| `app/platform/`       | 配置、DB、响应封装、异常、鉴权基础、凭据存储、运行规则   |
| `app/modules/`        | 按业务域组织的 `router / service / repository / schemas` |
| `app/worker/`         | 任务认领、心跳、执行编排、oracle 判定、报告聚合          |
| `app/worker/runtime/` | 工作目录准备、runtime 启停、dispatch 适配器、产物采集    |
| `app/api/`            | `/api` 与 `/api/v1` 路由聚合                             |
| `app/models/`         | SQLAlchemy 模型                                          |
| `alembic/`            | 数据库迁移                                               |
| `scripts/`            | 数据导入、QA 联调和烟测脚本                              |
| `tests/`              | API、模块、worker、脚本与架构回归测试                    |

## 3. 请求链路

典型请求处理链路如下：

1. `app/main.py` 初始化 FastAPI、locale middleware、静态目录和全局异常处理
2. `app/api/router.py` 将路由统一挂到 `/api`
3. `app/api/v1/api.py` 将业务接口挂到 `/api/v1`
4. `app/platform/i18n/LocaleMiddleware` 读取 `X-App-Locale`，建立请求级 locale 上下文
5. 路由通过 `app/platform/auth.py:get_db` 与 `app/modules/auth/dependencies.py:get_current_user` 注入会话和登录态
6. 各业务路由进入 `app/modules/*`，由 service 编排、repository 访问数据库
7. 成功响应统一使用 `app.platform.http.success_payload()`，业务异常统一抛 `DomainError` 子类
8. JSON 响应统一补 `Content-Language` 与 `Vary: X-App-Locale`，异常响应由统一翻译入口生成 `message`

当前业务模块包括 `auth / user / datasets / agents / evaluations / scoring / difficulty / leaderboards`。

## 4. 执行链路

当前主链路支持 API Agent 注册、验证、创建评测并由 worker 按冻结配置调用外部 Agent；本地 e2e 仍可通过脚本切换为 synthetic runtime 闭环。

1. `POST /api/v1/agents` 创建可验证的 Agent 配置，`POST /api/v1/evaluations` 创建 `test_runs`、`run_datasets`、`run_samples`、`sample_executions`
2. `app/worker/claims.py` 认领可执行任务，`app/worker/runner.py` 维持主循环
3. `app/worker/processing.py` 按数据集顺序驱动样本执行
4. `app/worker/execution.py` 准备工作目录、拉起 probe backend，并通过 `external_agent_api` 或本地 synthetic dispatch 执行样本
5. `app/worker/runtime/artifacts.py` 收集基础产物并写入 `execution_artifacts`
6. `app/worker/oracle_evaluator.py` 消费 `sample_oracles` 与 runtime 产物，写入 `oracle_results`、`execution_summaries`
7. `app/modules/evaluations/lifecycle.py` 汇总任务级报告，刷新样本难度统计，并在可评分时写入评测评分
8. `/api/v1/evaluations/*`、`/api/v1/evaluations/{evaluationId}/score*`、`/api/v1/difficulty/*`、`/api/v1/leaderboards/*` 对外提供任务、评分、难度版本与排行榜能力

## 5. 当前已落地能力

- 用户认证：注册、登录、当前用户
- 后端国际化运行时：`X-App-Locale` 请求级 locale、JSON 语言响应头、异常翻译入口和首批后端生成文案本地化
- 用户资料：资料查询、资料修改、头像上传
- 数据集目录与详情：`/api/v1/datasets/*`
- Agent 模板、注册、详情、列表、真实轻量验证与归档：`/api/v1/agents/*`
- 评测元数据、提交校验、创建、列表、详情与动作控制：`/api/v1/evaluations/*`
- 评测评分查询与重算：`/api/v1/evaluations/{evaluationId}/score*`
- 动态难度版本重算与发布：`/api/v1/difficulty/*`
- 排行榜快照生成与当前榜单查询：`/api/v1/leaderboards/*`
- PostgreSQL 轮询版独立 worker
- `var/backend/workdir` 工作目录准备、样本目录复制、probe backend 拉起
- `external_agent_api` 外部 API Agent 调用、`synthetic_local` dispatch 闭环、基础产物采集、`oracle_results` 与 `execution_summaries` 写回
- 外部 Agent 出站 HTTP SSRF 防护：`AGENT_HTTP_ALLOW_PRIVATE_NETWORKS`、`AGENT_HTTP_MAX_REDIRECTS`、`AGENT_HTTP_RESPONSE_MAX_BYTES`
- `run_reports.summary_json` 任务级聚合摘要

## 6. 当前未落地或仍需生产化

- Docker 运行链：当前不作为公开提交能力，未落地镜像拉起、认证注入和运行期隔离
- 外部 API Agent 证据链：基础调用已接入，调用日志、失败分型、外部响应证据归档仍需增强
- 样本级 execution 查询接口：当前仅有任务级列表、详情、动作、评分和报告摘要
- 报告文件导出：`run_reports.report_uri` 当前仍为空
- 动态难度治理：已有统计回刷、版本重算和发布基础链路，仍缺审计、审批、回滚和异常样本治理
- worker 生产观测：仍需健康检查、告警、异常恢复和队列方案评估

## 7. 核心约束

- 新增公共 API 路由必须使用 `/api/v1`
- 业务响应统一为 `{ code, data, message }`
- 后端 origin 只使用 `X-App-Locale` 决定响应语言；`Accept-Language` 由前端或网关归一化后写入 `X-App-Locale`
- 所有 JSON 响应必须带 `Content-Language` 与 `Vary: X-App-Locale`
- 鉴权和 DB Session 复用 `get_current_user`、`get_db`
- 数据库结构变更必须通过 Alembic 迁移交付
- 新增模型后先注册到 `app/models/__init__.py`
