# 后端架构说明

本文档说明 `backend/` 当前已经落地的后端结构、核心分层和公共约束。

## 1. 运行入口

- 应用入口：`app/main.py`
- API 根路由注册：`app/api/router.py`
- v1 路由注册：`app/api/v1/api.py`
- DB Session：`app/db/session.py`
- 统一响应工具：`app/api/response.py`

当前公开 API 路由前缀为 `/api/v1`。

## 2. 分层结构

| 目录 | 职责 |
| --- | --- |
| `app/api/` | 路由、依赖注入、响应封装 |
| `app/schemas/` | Pydantic 请求/响应模型 |
| `app/crud/` | 基础数据库读写操作 |
| `app/services/` | 业务编排、状态机、目录聚合、模拟执行 |
| `app/models/` | SQLAlchemy 模型 |
| `app/db/` | 数据库引擎与 Session 工厂 |
| `app/core/` | 配置、安全与通用基础能力 |
| `alembic/` | 数据库迁移 |
| `tests/` | 基础测试 |

## 3. 请求链路

典型请求处理链路如下：

1. `app/main.py` 挂载 FastAPI、静态目录和异常处理
2. `app/api/router.py` 将路由统一挂到 `/api`
3. `app/api/v1/api.py` 将业务接口挂到 `/api/v1`
4. 各 endpoint 通过 `app/api/deps.py` 注入 `get_db`、`get_current_user`
5. endpoint 调用 `schemas` 做通信模型约束，调用 `services` 处理业务编排与状态机
6. 成功返回使用 `success()` 包装，业务失败优先使用 `fail()` / `unauthorized()`

## 4. 当前已落地能力

- 用户认证：注册、登录、当前用户
- 用户资料：个人资料查询、资料修改、头像上传
- 数据集目录与详情：`/api/v1/datasets/*`
- 提交元数据、预检查与正式提交：`/api/v1/agents/*`
- 评测列表、详情与动作控制：`/api/v1/evaluations/*`
- 测评基础数据与运行态表模型
- 进程内联调执行器、本地凭证引用存储
- Alembic 迁移链路

## 5. 核心约束

- 新增公共 API 路由必须使用 `/api/v1`
- 业务接口返回结构统一为 `{ code, data, message }`
- 鉴权与 DB Session 复用 `get_current_user`、`get_db`
- 业务错误优先使用 `fail()`、`unauthorized()`
- 数据库结构变更必须通过 Alembic 迁移交付
- 新增模型后先注册到 `app/models/__init__.py`
