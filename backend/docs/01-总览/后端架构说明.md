# 后端架构说明

本文档说明 `backend/` 当前已经落地的后端结构、核心分层和公共约束。当前代码已按 `shared / modules / worker` 三条主线重组。

## 1. 运行入口

- 应用入口：`app/main.py`
- API 根路由注册：`app/api/router.py`
- v1 路由注册：`app/api/v1/api.py`
- Shared 配置与运行目录：`app/shared/config.py`、`app/shared/runtime.py`
- DB Session：`app/shared/db/session.py`
- 统一响应与异常：`app/shared/http.py`、`app/shared/errors.py`、`app/shared/exception_handlers.py`
- worker 入口：`app/worker/main.py`

当前公开 API 路由前缀为 `/api/v1`。

## 2. 分层结构

| 目录 | 职责 |
| --- | --- |
| `app/shared/` | 配置、DB、响应封装、异常、鉴权、共用规则与基础设施 |
| `app/modules/` | 按业务域组织的 `router / service / repository / schemas` |
| `app/worker/` | 任务领取、心跳、执行编排、报告聚合 |
| `app/api/` | API 根路由注册 |
| `app/models/` | SQLAlchemy 模型 |
| `alembic/` | 数据库迁移 |
| `tests/` | HTTP 契约、shared、worker 与模型回归测试 |

## 3. 请求链路

典型请求处理链路如下：

1. `app/main.py` 挂载 FastAPI、静态目录和异常处理
2. `app/api/router.py` 将路由统一挂到 `/api`
3. `app/api/v1/api.py` 将业务接口挂到 `/api/v1`
4. 路由通过 `app/shared/auth.py` 注入 `get_db`、`get_current_user`
5. 各业务路由进入 `app/modules/*`，由 service 编排、repository 访问数据库
6. 成功返回统一用 `app.shared.http.success_payload()` 包装；业务异常统一抛 `DomainError` 子类并由全局 handler 转成 envelope
7. 任务创建后由独立 worker 轮询 `test_runs` 领取执行，Web 进程只负责写入状态和读取快照

## 4. 当前已落地能力

- 用户认证：注册、登录、当前用户
- 用户资料：个人资料查询、资料修改、头像上传
- 数据集目录与详情：`/api/v1/datasets/*`
- 提交元数据、预检查与正式提交：`/api/v1/agents/*`
- 评测列表、详情与动作控制：`/api/v1/evaluations/*`
- 测评基础数据与运行态表模型
- PostgreSQL 轮询版独立 worker
- 本地文件凭证存储接口化实现
- Alembic 迁移链路

## 5. 核心约束

- 新增公共 API 路由必须使用 `/api/v1`
- 业务接口返回结构统一为 `{ code, data, message }`
- 鉴权与 DB Session 复用 `get_current_user`、`get_db`
- 所有业务响应统一为 `{ code, data, message }`
- 校验错误与未捕获异常也必须输出统一 envelope
- 数据库结构变更必须通过 Alembic 迁移交付
- 新增模型后先注册到 `app/models/__init__.py`
