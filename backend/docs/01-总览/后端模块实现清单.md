## 2. 后端总览

### 2.1 顶层目录与职责

| 目录/部分 | 作用 | 当前状态 |
| --- | --- | --- |
| `app/api` | 顶层 `/api` 与 `/api/v1` 路由聚合 | 已实现 |
| `app/shared` | 配置、DB、鉴权、响应、异常、凭据、运行规则 | 已实现 |
| `app/models` | ORM 模型与 Alembic 发现入口 | 部分实现 |
| `app/modules` | 按业务域拆分的 `router/service/repository/schemas` | 已实现 |
| `app/worker` | 任务认领、心跳、执行编排、报告汇总 | 部分实现 |
| `app/worker/runtime` | 工作目录、runtime 进程、dispatch、artifact 收集 | 部分实现 |
| `app/worker/runtimes` | 历史 runtime 分层残留目录 | 仅预留 |
| `scripts` | 导入、同步、联调、烟测脚本 | 已实现 |
| `data/**/agent_runtime` | 样本侧 runtime 家族，负责编译/回放/页面模板 | 部分实现 |
| `tests` | API、模块、worker、脚本、架构边界回归 | 已实现 |

### 2.2 两条主链路

请求链路：

1. `app/main.py` 启动 FastAPI 并挂载异常处理、静态目录和 `/api`
2. `app/api/router.py` 聚合 `/api`
3. `app/api/v1/api.py` 注册 `auth / user / datasets / agents / evaluations`
4. 业务请求进入 `app/modules/*`
5. `service` 编排业务逻辑，`repository` 访问数据库
6. `app.shared.http.success_payload()` 和全局异常处理器输出统一 envelope

执行链路：

1. `POST /api/v1/agents/submit` 创建 `test_runs`、`run_datasets`、`run_samples`、`sample_executions`
2. `app/worker/claims.py` 认领可执行任务，`app/worker/runner.py` 维持主循环
3. `app/worker/processing.py` 按数据集顺序执行
4. `app/worker/execution.py` 准备 runtime 工作目录、拉起 probe backend、执行 dispatch
5. `app/worker/runtime/artifacts.py` 收集基础产物并写 `execution_artifacts`
6. `app/modules/evaluations/lifecycle.py` 汇总 `execution_summaries`、`run_reports.summary_json`

### 3.2 关键实现入口补充

- `app/shared/credentials.py`
  - 当前只完成“存 / 取 / 删”本地密文凭据能力。
  - 提交链路会写入 `credential_ref`，worker 尚未读取。

- `app/worker/runtime/dispatch.py`
  - `SyntheticLocalDispatchAdapter` 已实际用于本地闭环。
  - `DeferredDispatchAdapter` 已存在，但当前提交链路不会自动使用它。

- `app/worker/runtimes/`
  - 当前仓库只剩 `__pycache__` 字节码残留，没有可维护源码。
  - 文档应将其视为历史痕迹或预留目录，而不是当前主链实现。

| 难度调整算法 | `datasets/importer.py`、`shared/runtime_rules.py`、`submissions/repository.py` | 入库时计算静态难度，提交时按 `difficulty ± 0.05` 选样 | 部分实现 | 无 `sample_difficulty_stats` 回刷逻辑 |
| 被测 Agent API 调用 | `submissions/service.py`、`shared/credentials.py` | 只开放提交契约并存储 `agent_base_url / credential_ref` | 仅预留 | worker 未真实调用外部 Agent |
| Docker 提交链路 | `submissions/schemas.py`、`submissions/service.py` | 只校验 `image_uri` 并落库 | 仅预留 | 无镜像拉起、认证注入和清理 |
| execution 证据查询 | `execution_artifacts` 模型、worker 产物写回 | 基础产物已落库 | 部分实现 | 无样本级 execution 查询 API |
| report 导出 | `evaluations/lifecycle.py`、`RunReport` 模型 | 只生成 `summary_json` 摘要 | 部分实现 | `report_uri` 始终为空 |

## 5. 预留与未实现清单

- `submit_method = "docker"` 只到入参、校验和落库，未进入真实执行链
- `credential_ref` 已存储，但 worker 不会加载凭据去调用真实 API 或 Docker Registry
- `oracle_results` 表已存在，当前没有写入逻辑
- `SampleDifficultyStat` 表已存在，当前没有统计任务更新 `inferred_difficulty`
- `retryEnabled` 已保存到 `execution_config.parameters`，但实际只创建 `retry_no = 0`
- `score` 在评测列表和详情接口里仍固定为 `null`
- `RunReport.report_uri` 当前始终为空
- `DeferredDispatchAdapter` 已有基础实现，但不是当前主链默认模式
- `app/worker/runtimes/` 当前仅剩 `__pycache__`，不应视为有效源码实现
