## 2. 后端总览

| 目录/部分 | 作用 | 当前状态 |

| `app/api` | 顶层 `/api` 与 `/api/v1` 路由聚合 | 已实现 |
| `app/platform` | 配置、DB、鉴权基础、响应、异常、凭据、运行规则 | 已实现 |
| `app/models` | ORM 模型与 Alembic 发现入口 | 已实现 |

| `app/worker/runtime` | 工作目录、runtime 进程、dispatch、artifact 收集 | 部分实现 |

| `tests` | API、模块、worker、脚本、架构边界回归 | 已实现 |

### 2.2 两条主链路

请求链路：

1. `app/main.py` 启动 FastAPI 并挂载异常处理、静态目录和 `/api`
2. `app/api/router.py` 聚合 `/api`
3. `app/api/v1/api.py` 注册 `auth / user / datasets / agents / evaluations / scoring / difficulty / leaderboards`
4. 业务请求进入 `app/modules/*`
5. `service` 编排业务逻辑，`repository` 访问数据库
6. `app.platform.http.success_payload()` 和全局异常处理器输出统一 envelope

执行链路：

1. `POST /api/v1/agents` 注册 Agent，`POST /api/v1/evaluations` 创建 `test_runs`、`run_datasets`、`run_samples`、`sample_executions`
2. `app/worker/claims.py` 认领可执行任务，`app/worker/runner.py` 维持主循环
3. `app/worker/processing.py` 按数据集顺序执行
4. `app/worker/execution.py` 准备 runtime 工作目录、拉起 probe backend、执行 dispatch
5. `app/worker/runtime/artifacts.py` 收集基础产物并写 `execution_artifacts`
6. `app/worker/oracle_evaluator.py` 消费 `sample_oracles` 与 runtime 产物，写 `oracle_results`、`execution_summaries`
7. `app/modules/evaluations/lifecycle.py` 汇总 `execution_summaries`、`run_reports.summary_json`，刷新样本难度统计，并尝试写入评测评分

### 3.2 关键实现入口补充

- `app/platform/credentials.py`
  - 当前完成“存 / 取 / 删”本地密文凭据能力。
  - Agent 注册链路会写入 `credential_ref`，验证和 worker 外部 API 调用会读取该引用。

- `app/modules/agents/security.py`
  - 当前负责外部 Agent base URL 的 SSRF 防护。
  - 默认仅允许 `http/https`，拒绝 localhost、回环、内网、链路本地、保留和未指定地址；如需私网联调必须显式配置 `AGENT_HTTP_ALLOW_PRIVATE_NETWORKS=true`。

- `app/worker/runtime/dispatch.py`
  - `SyntheticLocalDispatchAdapter` 已实际用于本地闭环。
  - `ExternalAgentApiDispatchAdapter` 已实际用于 API Agent 主链。
  - `DeferredDispatchAdapter` 已存在，但当前提交链路不会自动使用它。

- `app/modules/scoring/service.py`
  - `calculate_and_store_evaluation_score()` 会读取终态样本执行摘要并写入 `evaluation_scores`。
  - `GET /api/v1/evaluations/{evaluationId}/score` 只返回已存在评分；未评分时需要先重算或等待终态汇总链路写入。

- `app/modules/difficulty/service.py`
  - `update_sample_difficulty_stats_for_run()` 会按评测运行结果刷新 `sample_difficulty_stats`。
  - 难度版本发布会更新 `benchmark_samples.difficulty_score`。

## 4. 专项能力盘点

| 模块/能力 | 已有实现文件 | 当前只做到哪一步 | 当前状态 | 明显未落地部分 |
| --- | --- | --- | --- | --- |
| 数据导入 | `app/modules/datasets/ingestion/*`、`scripts/import_datasets.py`、`scripts/datasets/*` | 样本标准化、元数据同步、元数据导入、样本与 `sample_oracles` 入库 | 已实现 | 不负责启动运行态 |
| 隔离环境创建 | `app/worker/runtime/preparation.py`、`process.py`、`ports.py` | 为 execution 创建独立 workdir、端口、probe token、environment_ref | 部分实现 | 不是容器编排；真实 Docker 运行链未接入 |
| 样本运行 | `app/worker/execution.py`、`runtime/dispatch.py`、`modules/agents/invocation.py` | `external_agent_api` 可调用外部 API Agent；`synthetic_local` 可以闭合 runtime 运行、finalize 和回放结果 | 部分实现 | Docker 驱动未实现，外部调用证据仍需增强 |
| 评分 / oracle | `app/worker/oracle_evaluator.py`、`sample_oracles`、`oracle_results`、`ExecutionSummary`、`app/modules/scoring/*` | 执行 `event_trace_match / completion_signal / manual_review / llm_judge`，写明细、汇总和评测级评分 | 部分实现 | `llm_judge` 低置信或配置缺失时仍进入待复核；评分治理仍需生产化 |
| 难度调整算法 | `app/platform/runtime_rules.py`、`app/modules/difficulty/*`、`evaluations/repository.py` | 入库初始化难度，提交时按难度桶选样，运行后回刷统计，版本重算/发布 | 部分实现 | 缺审计、审批、回滚和异常样本治理 |
| 被测 Agent API 调用 | `modules/agents/*`、`worker/runtime/dispatch.py`、`platform/credentials.py` | 注册时保存非敏感配置与凭据引用，验证和 worker 均可真实调用外部 Agent | 已实现 | 调用日志、失败分类和外部响应证据归档仍需增强 |
| Docker 运行链路 | `submit_method` 预留值、模型字段 | 当前不作为公开提交能力 | 仅预留 | 无镜像拉起、认证注入和清理 |
| execution 证据查询 | `execution_artifacts` 模型、worker 产物写回 | 基础产物已落库 | 部分实现 | 无样本级 execution 查询 API |
| report 导出 | `evaluations/lifecycle.py`、`RunReport` 模型 | 已生成 `summary_json` 摘要 | 部分实现 | `report_uri` 仍为空 |
| 排行榜 | `app/modules/leaderboards/*`、`EvaluationScore`、`LeaderboardSnapshot` | 可从公开且已评分评测生成当前榜单，未登录可查看匿名安全字段 | 已实现 | 缺历史快照查询和管理权限 |

## 5. 预留与未实现清单

- `submit_method = "docker"` 当前不对外开放
- Docker Registry 凭据链路未实现
- 执行级重试仍只创建 `retry_no = 0`
- 样本级 execution 列表、详情和证据查询接口未实现
- `RunReport.report_uri` 当前仍为空
- `ExternalAgentApiDispatchAdapter` 是 API Agent 主链默认模式；`DeferredDispatchAdapter` 已有基础实现但不是当前主链默认模式
