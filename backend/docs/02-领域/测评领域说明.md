## 2. 当前仓库现状

### 已落地

- `data/datasets/` 保存标准样本、页面资源和各风险子类的 `agent_runtime` 插件目录
- `backend/dataset_metadata/` 保存版本化元数据 JSON 真源
- `POST /api/v1/agents`、`POST /api/v1/agents/{agentId}/verify`、`POST /api/v1/evaluations`、`GET /api/v1/evaluations`、`GET /api/v1/evaluations/{evaluationId}`、`POST /api/v1/evaluations/{evaluationId}/actions` 已对外开放
- worker 已具备任务认领、心跳续约、暂停/恢复/终止/取消、样本执行和任务级摘要写回能力
- `external_agent_api` 可以按冻结 Agent 配置调用外部 API Agent；`synthetic_local` 仍可闭合 runtime 启动、事件采集、finalize、回放结果生成和基础产物落库
- worker 已在样本执行结束后消费 `sample_oracles`，生成 `oracle_results` 与 `execution_summaries`

### 仍待补齐

- 真实 Docker 运行链
- 样本级 execution 查询接口
- `report_uri` 离线报告导出

## 3. 核心领域对象

- 样本：可执行的单个测评单元，包含用户目标、攻击目标、入口资源和 oracle 定义
- Agent：用户注册的外部 API Agent 调用配置，包含连接、映射、非敏感鉴权配置和凭据引用
- 任务：一次用户提交形成的评测 run，负责组织数据集、样本集合、执行配置和汇总结果
- 执行：某个样本在某次任务中的一次实际运行，可为后续重试预留
- oracle：样本定义层的判定规则集合，描述“安全完成”或“违规/受损”
- 报告：任务级聚合产物，用于沉淀统计、结论和证据引用

## 4. 样本运行框架

当前样本运行框架由两部分组成：

- `app/worker/runtime/*`
  - 负责创建 `runtime/workdir/<execution_id>`、分配端口、拉起统一 probe backend、收集基础产物
- `data/datasets/<风险大类>/<风险子类>/agent_runtime/*`
  - 只作为样本侧 `compiler.py / replay.py / template` 插件
  - worker 会把对应样本目录和所属风险子类的 `agent_runtime/` 复制到运行目录，再由统一 probe backend 调用

因此，`agent_runtime/` 是运行插件，不再作为独立后端入口；统一入口是 `app.worker.runtime.probe_backend`。

## 5. 任务执行生命周期

当前实现的任务级生命周期如下：

1. 用户注册并验证 API Agent，验证通过后 Agent 进入 `active`
2. 用户创建 Evaluation 时选择 `active` Agent、数据集和执行参数
3. 后端校验数据集筛选结果，冻结 Agent 非敏感配置到 `execution_config.frozenAgentSnapshot`，并创建 `test_runs`、`run_datasets`、`run_samples`、`sample_executions`
4. worker 认领任务并按数据集顺序驱动样本执行
5. runtime 为样本准备工作目录、入口 URL、环境标识，并拉起 probe backend
6. dispatch 触发 `external_agent_api` 或 `synthetic_local` 适配模式，完成外部 Agent 调用或本地编译/回放和基础证据收集
7. worker 写入 `execution_artifacts`，执行 oracle evaluator，写入 `oracle_results` 与 `execution_summaries`
8. 任务收尾时汇总 `run_reports.summary_json`，详情接口返回任务级快照和摘要

## 6. oracle 与结果语义

在领域层，oracle 只承担“规则定义”职责：

- `success`
  - 描述安全完成条件
- `harm`
  - 描述违规或受损条件

当前实现：

- `sample_oracles` 会在导入阶段入库
- worker 运行结束后按 `evaluator_type` 分派 evaluator
- `event_trace_match` 消费 `events.jsonl`
- `completion_signal` 消费 `finalize.json`
- `manual_review` / `llm_judge` 先生成待复核结果
- 每条规则写入 `oracle_results`，再汇总为 `execution_summaries`

当前结果语义：

- harm oracle 命中时写 `final_label = "hijacked"`
- success oracle 全部命中且无需复核时写 `final_label = "safe"`
- 含人工/LLM/完成信号复核项或证据不足时写 `final_label = "needs_review"`
- 超时写 `final_label = "timeout"`

## 7. 报告语义

当前 `run_reports` 只承担任务级摘要职责：

- `summary_json`
  - 已落地，包含总样本数、已完成数、任务完成数、损害检出数、按风险/攻击等级聚合等结构化摘要
- `report_uri`
  - 模型已预留，但当前不生产离线文件

因此，当前任务报告是“任务级聚合摘要”，不是完整离线报告导出链路。
