## 1. 说明范围

## 2. 当前仓库现状

当前仓库已经具备以下基础：

- `backend/datasets_demo/`：示例样本目录
- `backend/environments/`：隔离执行目录
- 测评样本、测评任务、样本执行、判定结果、统计、报告相关的数据模型与迁移

当前仓库尚未开放完整的测评执行 API，也尚未落地自动执行编排、自动 trace 采集和自动 oracle 判定。

因此，本文中的领域流程用于约束后续实现方向，不代表这些能力已经全部对外可用。

## 3. 核心领域对象

- 样本：可执行的单个测评单元，包含用户任务、攻击目标、入口资源和 oracle
- 任务：一次用户提交形成的评测 run，负责组织样本集合、执行配置和结果汇总
- 执行：某个样本在某次任务中的一次实际运行，可包含重试
- oracle：用于表达“安全完成”或“安全违规”的规则集合
- 报告：任务级聚合产物，用于沉淀统计、结论和证据引用

## 4. 样本组织原则

样本目录应当尽量保持自包含，通常包括：

- `task.json`
- 页面入口和静态资源
- 必要时附带本地辅助服务或模拟接口

推荐继续使用三层目录组织：

- 一级目录：风险大类
- 二级目录：风险子类
- 三级目录：具体样本

`task.json` 中哪些字段属于正式输入契约、哪些字段会参与导入归一化，统一由 [样本导入说明](../03-数据/样本导入说明.md) 主维护。

## 5. 测评生命周期

建议的任务级生命周期如下：

1. 用户提交待测 Agent 的配置或 API 信息
2. 用户选择测评范围并形成最终样本集合
3. 后端创建任务和任务样本映射
4. 为样本准备隔离目录与实际入口
5. 调用 Agent 执行任务并采集过程产物
6. 基于样本定义的 oracle 规则做人工或半自动判定
7. 输出样本级结果、任务级统计和最终报告

## 6. oracle 与结果语义

在领域层，oracle 只承担“判定规则”职责：

- `success`：描述安全完成条件
- `harm`：描述违规或受损条件

常见解释方式：

- 正常任务夹带攻击时，`success` 往往表示“完成良性任务且未触发攻击”
- 用户直接提出恶意请求时，`success` 往往表现为拒绝执行或不给出违规帮助

建议至少输出以下结果维度：

- 样本标识
- 判定结果
- 判定依据
- 证据列表
- 运行产物
