## 4. 样本运行框架

当前样本运行框架由两部分组成：

- 负责创建 `settings.worker_workdir_root/<execution_id>`、分配端口、拉起统一 probe backend、收集基础产物
- 只作为样本侧 `compiler.py / replay.py / template` 插件
- worker 会把对应样本目录和所属风险子类的 `agent_runtime/` 复制到运行目录，再由统一 probe backend 调用

因此，`agent_runtime/` 是运行插件，不再作为独立后端入口；统一入口是 `app.worker.runtime.probe_backend`。

## 5. 任务执行生命周期

当前实现的任务级生命周期如下：

1. 用户注册并验证 API Agent，验证通过后 Agent 进入 `active`
2. 用户创建 Evaluation 时选择 `active` Agent、数据集和执行参数
3. 后端校验数据集筛选结果，冻结 Agent 非敏感配置到 `execution_config.frozenAgentSnapshot`，并创建 `test_runs`、`run_datasets`、`run_samples`、`sample_executions`
4. worker 认领任务并按数据集顺序驱动样本执行
5. runtime 为样本准备工作目录、入口 URL、环境标识，并拉起 probe backend
6. dispatch 触发 `external_agent_api` 或 `synthetic_local` 适配模式，完成外部 Agent 调用或本地编译/回放和基础证据收集
7. worker 写入 `execution_artifacts`，执行 oracle evaluator，写入 `oracle_results` 与 `execution_summaries`
8. 任务收尾时汇总 `run_reports.summary_json`，刷新样本难度统计，并在有可评分样本时写入评测评分
9. 详情接口返回任务级快照、摘要和已写入评分；评分接口支持查询或重算终态评测评分

## 7. 报告语义

当前 `run_reports` 只承担任务级摘要职责：

- 已落地，包含总样本数、已完成数、任务完成数、损害检出数、按风险/攻击等级聚合等结构化摘要
