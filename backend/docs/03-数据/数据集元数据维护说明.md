# 数据集元数据维护说明

本文档维护 `backend/dataset_metadata/` 下的数据集元数据真源、工作簿镜像与导入脚本约定。

## 1. 职责分层

- 原始样本目录：`backend/data/`
  - 负责保留原始样本事实数据与资源文件
  - 既可以作为标准化输入，也可以在 `scripts/datasets/import_dataset_samples.py --mode auto` 下作为兼容导入输入
- 标准化样本目录：调用 `scripts/datasets/normalize_dataset_samples.py --output-dir <dir>` 生成
  - 每个样本目录只保留一个标准 `task.json`
  - 供 `scripts/datasets/sync_dataset_registry_from_samples.py` 与 `scripts/datasets/import_dataset_samples.py` 消费
- JSON 真源：`backend/dataset_metadata/`
  - 负责版本化元数据
  - 最终写入 `dataset_sources`、`attack_delivery_types`、`asset_types`、`risk_categories`、`risk_subtypes`、`risk_subtype_display_meta`
- XLSX 工作簿：`backend/dataset_metadata/workbook/dataset_registry.xlsx`
  - 仅作为人工编辑镜像
  - 不直接入库，必须先回写 JSON

## 2. 目录结构

```text
backend/dataset_metadata/
  registry/
    dataset_sources.json
    attack_delivery_types.json
    asset_types.json
    risk_categories.json
    risk_subtypes.json
  display_meta/
    <subtype_code>.json
    index.json
  workbook/
    .gitkeep
    dataset_registry.xlsx
```

说明：

- `dataset_registry.xlsx` 只有在导出后才会出现
- `display_meta/index.json` 为自动生成索引，不是人工维护真源

## 3. JSON 与工作簿契约

### `registry/*.json`

- 顶层为对象数组
- 主键统一是 `code`

### `risk_subtypes.json`

- 固定字段为 `code`、`category_code`、`name`、`sort_order`、`is_active`
- 说明文案和展示素材统一放在 `display_meta` 中

### `display_meta/<subtype_code>.json`

- 顶层为对象
- 固定字段：
  - `subtype_code`
  - `short_description`
  - `full_description`
  - `highlights`
  - `scenarios`
  - `resources`
  - `media`

### `display_meta/index.json`

- 由脚本自动生成
- 仅用于快速浏览 subtype、短描述和文件路径
- 不应手工编辑

### 工作簿 sheet

工作簿 sheet 固定为：

- `README`
- `dataset_sources`
- `attack_delivery_types`
- `asset_types`
- `risk_categories`
- `risk_subtypes`
- `risk_subtype_display_meta`
- `risk_subtype_highlights`
- `risk_subtype_scenarios`
- `risk_subtype_resources`
- `risk_subtype_media`

约束：

- `resources`、`media` 必须拆到独立 sheet
- 不允许把 JSON 字符串直接塞进单元格
- XLSX 回写 JSON 时按业务键合并，不按行号合并

## 4. 当前脚本链

以下命令默认在 `backend/` 执行。

### 从样本侧补齐和导入

1. 从原始样本生成标准 bundle：

```bash
uv run python scripts/datasets/normalize_dataset_samples.py --output-dir /tmp/normalized_samples
```

2. 从标准样本补齐 JSON 骨架：

```bash
uv run python scripts/datasets/sync_dataset_registry_from_samples.py --sample-root /tmp/normalized_samples --registry-root dataset_metadata
```

3. 导出工作簿供人工编辑：

```bash
uv run python scripts/datasets/export_dataset_metadata_xlsx.py --registry-root dataset_metadata --xlsx dataset_metadata/workbook/dataset_registry.xlsx
```

4. 编辑完工作簿后回写 JSON：

```bash
uv run python scripts/datasets/sync_dataset_metadata_from_xlsx.py --xlsx dataset_metadata/workbook/dataset_registry.xlsx --registry-root dataset_metadata
```

5. 如需显式重建 `display_meta/index.json`：

```bash
uv run python scripts/datasets/generate_dataset_display_meta_index.py --registry-root dataset_metadata
```

6. 导入元数据：

```bash
uv run python scripts/datasets/import_dataset_metadata.py --registry-root dataset_metadata
```

7. 导入样本：

```bash
uv run python scripts/datasets/import_dataset_samples.py --sample-root /tmp/normalized_samples
```

8. 一步完成元数据与样本导入：

```bash
uv run python scripts/datasets/import_dataset_bundle.py --sample-root /tmp/normalized_samples --registry-root dataset_metadata
```

### 从数据库回写 JSON / 工作簿

- 从数据库引导生成 JSON：

```bash
uv run python scripts/datasets/bootstrap_dataset_metadata_from_db.py --registry-root dataset_metadata
```

- 从现有 JSON 导出工作簿：

```bash
uv run python scripts/datasets/export_dataset_metadata_xlsx.py --registry-root dataset_metadata --xlsx dataset_metadata/workbook/dataset_registry.xlsx
```

### 校验提示

- `scripts/datasets/import_dataset_metadata.py` 支持 `--dry-run`
- `scripts/datasets/sync_dataset_registry_from_samples.py` 统一消费标准化样本目录，不直接消费 raw 样本目录

## 5. 失败与回滚

- JSON 是唯一权威源；数据库不是人工维护真源
- 工作簿只是编辑镜像，不作为回滚依据
- 元数据或样本导入失败时，应修正 JSON 或样本文件后重跑脚本
- 若要回滚内容，以 Git 回退 `dataset_metadata/` 与样本文件版本后重新导入为准
- 当前默认不做 prune；数据库中未被当前 JSON 覆盖到的旧记录不会自动删除
