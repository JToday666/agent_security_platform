# 数据集元数据维护说明

本文档维护 `data/metadata/` 下的数据集元数据 JSON 真源与导入脚本约定。

## 1. 职责分层

- 一等样本目录：`data/datasets/`
  - 负责保留标准 `task.json`、网页资源和风险子类 `agent_runtime` 插件
  - 是顶层导入脚本的默认推荐输入
- 临时标准化样本目录：由 `scripts/datasets/normalize_samples.py --output-dir <dir>` 生成
  - 每个样本目录只保留一个标准 `task.json`
  - 供 `scripts/datasets/sync_metadata_from_samples.py` 与 `scripts/datasets/import_samples.py` 消费
- JSON 真源：`data/metadata/`
  - 是唯一可编辑真源
  - 最终写入 `dataset_sources`、`attack_delivery_types`、`asset_types`、`risk_categories`、`risk_subtypes`、`risk_subtype_display_meta`

## 2. 目录结构

```text
data/metadata/
  registry/
    dataset_sources.json
    attack_delivery_types.json
    asset_types.json
    risk_categories.json
    risk_subtypes.json
  display_meta/
    <subtype_code>.json
    index.json
```

说明：

- `registry/*.json` 与 `display_meta/*.json` 都属于版本化真源
- `display_meta/index.json` 是自动生成的浏览索引，不是人工编辑入口
- 任何元数据写回都会自动刷新 `display_meta/index.json`

## 3. JSON 契约

### `registry/*.json`

- 顶层为对象数组
- 主键统一使用稳定业务键，通常是 `code`

### `risk_subtypes.json`

- 固定字段为 `code`、`category_code`、`name`、`sort_order`、`is_active`
- 说明文案和展示素材统一放在 `display_meta` 中

### `display_meta/<subtype_code>.json`

- 顶层为对象
- 固定字段：
  - `subtype_code`
  - `short_description`
  - `full_description`
  - `highlights`
  - `scenarios`
  - `resources`
  - `media`

### `display_meta/index.json`

- 由脚本自动生成
- 用于快速浏览 subtype、短描述和文件路径
- 不应手工编辑

## 4. 推荐脚本链

以下命令默认在 `backend/` 执行。

### 顶层一键导入

唯一推荐入口：

```bash
uv run python scripts/import_datasets.py --sample-root <path>
```

行为固定为：

1. 自动识别输入是 raw 还是 standard
2. raw 输入时先标准化
3. 从样本补齐并回写 `data/metadata/`
4. 导入元数据
5. 导入样本

常用参数：

- `--registry-root`：默认 `data/metadata`
- `--mode`：默认 `auto`
- `--workspace-dir`：指定标准化工作目录
- `--dry-run`：只输出计划摘要，不写数据库

当前仓库数据集推荐命令：

```bash
uv run python scripts/import_datasets.py --sample-root ../data/datasets --dry-run
```

如需就地升级 legacy `task.json`：

```bash
uv run python scripts/datasets/standardize_task_json.py --sample-root ../data/datasets --write
```

### 分步脚本

1. 标准化样本：

```bash
uv run python scripts/datasets/normalize_samples.py --input-root ./data --output-dir /tmp/normalized_samples
```

2. 从标准样本补齐/回写 JSON 真源：

```bash
uv run python scripts/datasets/sync_metadata_from_samples.py --sample-root /tmp/normalized_samples --registry-root ../data/metadata
```

3. 导入元数据：

```bash
uv run python scripts/datasets/import_metadata.py --registry-root ../data/metadata
```

4. 导入样本：

```bash
uv run python scripts/datasets/import_samples.py --sample-root /tmp/normalized_samples --mode auto
```

5. 从数据库引导生成 JSON：

```bash
uv run python scripts/datasets/bootstrap_metadata_from_db.py --registry-root ../data/metadata
```

校验提示：

- `scripts/import_datasets.py` 与 `scripts/datasets/import_metadata.py` 都支持 `--dry-run`
- `scripts/datasets/sync_metadata_from_samples.py` 统一消费标准化样本目录，不直接消费 raw 样本目录

## 5. 失败与回滚

- JSON 是唯一权威源；数据库不是人工维护真源
- 元数据或样本导入失败时，应修正 JSON 或样本文件后重跑脚本
- 若要回滚内容，以 Git 回退 `data/metadata/` 与样本文件版本后重新导入为准
- 当前默认不做 prune；数据库中未被当前 JSON 覆盖到的旧记录不会自动删除
