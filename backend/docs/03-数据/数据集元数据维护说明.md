# 数据集元数据维护说明

本文档维护 `backend/dataset_metadata/` 下的数据集元数据真源、工作簿镜像与导入脚本约定。

## 1. 职责分层

- 样本目录：`backend/datasets_demo/` 或未来标准样本目录
  - 负责样本事实数据
  - 最终写入 `benchmark_samples`、`sample_oracles`
- JSON 真源：`backend/dataset_metadata/`
  - 负责版本化元数据
  - 最终写入 `dataset_sources`、`attack_delivery_types`、`asset_types`、`risk_categories`、`risk_subtypes`、`risk_subtype_display_meta`
- XLSX 工作簿：`backend/dataset_metadata/workbook/dataset_registry.xlsx`
  - 仅作为人工编辑镜像
  - 不直接入库，必须先回写 JSON

## 2. 目录结构

```text
backend/dataset_metadata/
  registry/
    dataset_sources.json
    attack_delivery_types.json
    asset_types.json
    risk_categories.json
    risk_subtypes.json
  display_meta/
    A1_identity_leakage.json
    A5_credentials_and_secrets_leakage.json
    B2_cloud_file_modification.json
    B5_identity_forgery_modification.json
    index.json
  workbook/
    .gitkeep
```

## 3. JSON 契约

- `registry/*.json`
  - 顶层为对象数组
  - 主键统一是 `code`
- `risk_subtypes.json`
  - 固定字段为 `code`、`category_code`、`name`、`sort_order`、`is_active`
  - 不再承载说明文案，展示说明统一放在 `display_meta` 中
- `display_meta/<subtype_code>.json`
  - 顶层为对象
  - 固定字段：
    - `subtype_code`
    - `short_description`
    - `full_description`
    - `highlights`
    - `scenarios`
    - `resources`
    - `media`
- `display_meta/index.json`
  - 为自动生成的导航索引，不是权威真源
  - 仅用于快速浏览 subtype、短描述和文件路径
  - 不应手工编辑；需要刷新时重新运行脚本

## 4. 工作簿结构

工作簿 sheet 固定为：

- `README`
- `dataset_sources`
- `attack_delivery_types`
- `asset_types`
- `risk_categories`
- `risk_subtypes`
- `risk_subtype_display_meta`
- `risk_subtype_highlights`
- `risk_subtype_scenarios`
- `risk_subtype_resources`
- `risk_subtype_media`

约束：

- `resources`、`media` 必须拆到独立 sheet
- 不允许把 JSON 字符串直接塞进单元格
- XLSX 回写 JSON 时按业务键合并，不按行号合并

## 5. 脚本顺序

以下命令默认在 `backend/` 执行：

1. 从样本补齐 JSON 骨架：

```bash
uv run python scripts/sync_dataset_registry_from_samples.py --sample-root datasets_demo --registry-root dataset_metadata
```

2. 导出工作簿供人工编辑：

```bash
uv run python scripts/export_dataset_metadata_xlsx.py --registry-root dataset_metadata --xlsx dataset_metadata/workbook/dataset_registry.xlsx
```

3. 如需显式重建 `display_meta/index.json`：

```bash
uv run python scripts/generate_dataset_display_meta_index.py --registry-root dataset_metadata
```

4. 编辑完工作簿后回写 JSON：

```bash
uv run python scripts/sync_dataset_metadata_from_xlsx.py --xlsx dataset_metadata/workbook/dataset_registry.xlsx --registry-root dataset_metadata
```

5. 导入元数据：

```bash
uv run python scripts/import_dataset_metadata.py --registry-root dataset_metadata
```

6. 导入样本：

```bash
uv run python scripts/import_dataset_samples.py --sample-root datasets_demo
```

7. 一步完成元数据与样本导入：

```bash
uv run python scripts/import_dataset_bundle.py --sample-root datasets_demo --registry-root dataset_metadata
```

## 6. 失败与回滚

- JSON 是唯一权威源；数据库不是人工维护真源
- 工作簿只是编辑镜像，不作为回滚依据
- 元数据或样本导入失败时，应修正 JSON 或样本文件后重跑脚本
- 若要回滚内容，以 Git 回退 `dataset_metadata/` 与样本文件版本后重新导入为准
- 当前默认不做 prune；数据库中未被当前 JSON 覆盖到的旧记录不会自动删除
