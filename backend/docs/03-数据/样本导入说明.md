# 样本导入说明

本文档只维护样本如何入库，不维护样本领域语义和运行流程。
样本领域语义见 [测评领域说明](../02-领域/测评领域说明.md)，表结构见 [数据库说明](./数据库说明.md)。

`data/datasets/` 是当前唯一一等样本源。后端通过 `settings.DATASET_ROOT_DIR` 覆盖该路径，未配置时默认指向仓库根目录下的 `data/datasets`。

当前推荐直接使用顶层脚本：

```bash
uv run python scripts/import_datasets.py --sample-root ../data/datasets
```

该入口会自动识别输入是 raw 还是 standard；raw 输入会先标准化，再回写/补齐 `dataset_metadata/`，最后依次导入元数据和样本。

如需把 legacy `task.json` 就地升级为标准 schema，使用：

```bash
uv run python scripts/datasets/standardize_task_json.py --sample-root ../data/datasets --write
```

该脚本只处理样本根目录的 `task.json`，同目录其它 JSON 默认视为网页或场景资源。

底层导入链仍支持两种输入方式：

- 推荐方式：先通过 `scripts/datasets/normalize_samples.py` 产出标准 bundle，再交给后续脚本消费
- 兼容方式：`scripts/datasets/import_samples.py --mode auto` 直接扫描 raw / standard 样本目录

其中，标准化 bundle 仍是最适合版本化回归、元数据同步和可重复导入的主路径。

## 1. 导入边界

当前样本导入器只应写入样本域 2 张表：

- `benchmark_samples`
- `sample_oracles`

以下 6 张元数据表由 `dataset_metadata/` 下的版本化 JSON 导入链负责维护，不由样本导入器直接写入：

- `dataset_sources`
- `attack_delivery_types`
- `asset_types`
- `risk_categories`
- `risk_subtypes`
- `risk_subtype_display_meta`

样本导入阶段不应写入 Agent 配置表或运行态表：

- `agents`
- `test_runs`
- `run_datasets`
- `run_samples`
- `sample_executions`
- `execution_artifacts`
- `oracle_results`
- `execution_summaries`
- `sample_difficulty_stats`
- `run_reports`

## 2. 输入模式与扫描规则

样本扫描以目录内的 `task.json` 为唯一元数据入口：

- 目录存在 `task.json` 时，只读取该文件
- 同目录其它 JSON 视为网页、业务或场景资源，不参与元数据冲突判定
- 只有 legacy 迁移模式才允许在没有 `task.json` 的目录中扫描其它 JSON 元数据

### 标准化输入

推荐的可重复流程：

```bash
uv run python scripts/datasets/normalize_samples.py --output-dir /tmp/normalized_samples
uv run python scripts/datasets/sync_metadata_from_samples.py --sample-root /tmp/normalized_samples --registry-root dataset_metadata
uv run python scripts/datasets/import_metadata.py --registry-root dataset_metadata
uv run python scripts/datasets/import_samples.py --sample-root /tmp/normalized_samples
```

约束：

- `scripts/datasets/normalize_samples.py` 输出目录必须是显式指定的空目录
- `scripts/datasets/sync_metadata_from_samples.py` 统一消费标准化后的样本目录

### 兼容输入

允许直接导入原始样本目录：

```bash
uv run python scripts/datasets/import_metadata.py --registry-root dataset_metadata
uv run python scripts/datasets/import_samples.py --sample-root ./data/02_Integrity/B2_Cloud_File_Modification --mode auto
```

说明：

- `--mode auto` 会自动识别 raw / standard 两类样本目录
- 这条链更适合本地引导或快速联调，不是推荐的长期版本化主路径

## 3. 标准输入契约

一个标准样本目录至少包含：

- 样本根目录
- 根目录下的 `task.json`
- 页面、资源、脚本和必要的辅助文件

推荐的 `task.json` 输入字段：

| 字段 | 说明 |
| --- | --- |
| `schema_version` | 当前固定为 `1.0` |
| `sample_id` | 样本稳定编号 |
| `sample_name` | 展示名称，可选 |
| `dataset_source_code` | 来源 code |
| `dataset_source_name` | 来源展示名，可选 |
| `entry_path` | 相对样本根目录的入口路径 |
| `user_goal` | 用户目标 |
| `attacker_goal` | 攻击目标，可选 |
| `attacker_is_user` | 是否为同一主体 |
| `attack_delivery_type_code` | 攻击投递方式 code |
| `attack_delivery_type_name` | 攻击投递方式展示名，可选 |
| `risk_category_code` | 风险大类 code |
| `risk_category_name` | 风险大类展示名，可选 |
| `risk_category_sort_order` | 风险大类排序值，可选 |
| `risk_subtype_code` | 风险子类 code |
| `risk_subtype_name` | 风险子类展示名，可选 |
| `risk_subtype_sort_order` | 风险子类排序值，可选 |
| `risk_level` | `low / medium / high` |
| `attack_level` | `low / medium / high` |
| `asset_type_code` | 资产类型 code，可选 |
| `asset_type_name` | 资产类型展示名，可选 |
| `expected_safe_behavior` | 预期安全行为 |
| `oracles` | 规则列表，不能为空 |

`oracles[]` 元素至少应包含：

- `kind`：`success` 或 `harm`
- `seq_no`
- `display_text`
- `evaluator_type`
- `evaluator_config`

## 4. 归一化规则

### 4.1 code 规则

- 所有 `*_code` 都按稳定 ASCII 标识入库
- 常见格式是字母、数字和下划线，例如 `eia`、`browser_art`、`B2_cloud_file_modification`
- 历史样本中的展示文本、目录名或旧字段会在入库前转换为正式 code

### 4.2 等级规则

- `risk_level` / `attack_level` 映射为数据库中的 `1 / 2 / 3`
- `low -> 1`
- `medium -> 2`
- `high -> 3`

### 4.3 难度初始化

当前导入器会在入库阶段同时写 `difficulty_seed` 和 `difficulty_score`：

- 先把 `risk_level`、`attack_level` 归一化到 `0~1`
- 再按公式计算：
  - `difficulty = 0.35 * risk_norm + 0.65 * attack_norm`
- 最终保留三位小数并夹到 `0~1`

说明：

- 这是样本入库时的静态初值
- 当前没有 `sample_difficulty_stats` 驱动的动态回刷逻辑

### 4.4 oracle 规则

- `oracles.kind` 映射为 `sample_oracles.oracle_kind`
  - `success -> 1`
  - `harm -> 2`
- `event_trace_match`：根据 `events.jsonl` 匹配事件类型、target 子集、`value_equals` 和顺序约束
- `completion_signal`：根据 `finalize.json` 的 `done=true` 生成保守完成信号，最终仍标记为 `needs_review`
- `manual_review` / `llm_judge`：入库后保留准则，运行结束时生成待复核结果

### 4.5 兼容旧字段

旧样本兼容输入可接受以下字段，但只作为迁移来源：

- `dataset_source`
- `attack_delivery`
- `primary_risk`
- `secondary_risk`
- `success_oracle`
- `harm_oracle`

兼容字段在入库前必须先转换为标准字段，不直接写库。

旧字段转换规则：

- 对象型 `success_oracle` / `harm_oracle` 聚合为 `event_trace_match`，条件写入 `evaluator_config.conditions`
- 字符串型 oracle 转为 `manual_review`，原文保存在 `display_text` 和 `evaluator_config.criteria`
- 空 `success_oracle` 转为 `completion_signal`，用于 VPI 等缺少成功 oracle 的样本

## 5. 入库映射

### 字典表查找

- `dataset_source_code -> dataset_sources.code`
- `attack_delivery_type_code -> attack_delivery_types.code`
- `risk_category_code -> risk_categories.code`
- `risk_subtype_code -> risk_subtypes.code`
- `asset_type_code -> asset_types.code`

样本导入前，以上 code 必须已由元数据导入脚本写入数据库；样本导入器不负责隐式补齐这些字典记录。

### `benchmark_samples`

关键映射：

- `sample_id -> sample_id`
- `sample_name -> sample_name`
- 样本根目录相对路径 -> `resource_path`
- `entry_path -> entry_path`
- `user_goal -> user_goal`
- `attacker_goal -> attacker_goal`
- `attacker_is_user -> attacker_is_user`
- 字典 code 查找结果 -> `dataset_source_id`、`attack_delivery_type_id`、`risk_subtype_id`、`asset_type_id`
- `risk_level` / `attack_level` 归一化后入库
- 静态难度初始化 -> `difficulty_seed`、`difficulty_score`
- `expected_safe_behavior -> expected_safe_behavior`
- `is_active` 默认 `true`

幂等唯一键：

- `dataset_source_id + sample_id`

### `sample_oracles`

关键映射：

- 目标样本主键 -> `sample_id_ref`
- `kind -> oracle_kind`
- `seq_no -> seq_no`
- `display_text -> display_text`
- `evaluator_type -> evaluator_type`
- `evaluator_config -> evaluator_config`
- `is_active` 默认 `true`

幂等唯一键：

- `sample_id_ref + oracle_kind + seq_no`

## 6. 回退与失败规则

`entry_path` 的回退解析只用于兼容旧样本：

1. 使用显式提供的 `entry_path`
2. 若样本根目录下存在唯一 `index.html`，可回退为 `index.html`
3. 无法确定唯一入口时，导入失败

出现以下情况时必须拒绝写入：

- 标准 `task.json` 缺失 `schema_version`
- 缺失 `sample_id`
- 缺失 `dataset_source_code`
- 无法推导 `resource_path`
- 无法确定 `entry_path`
- 无法归一化任一 `*_code`
- `risk_level` 或 `attack_level` 不在 `low / medium / high`
- `oracles` 为空，或 oracle 无法补齐正式对象

## 7. 实现边界

样本导入器负责：

- 扫描样本源
- 归一化字典值和等级值
- 校验样本引用的 code 已在数据库中注册
- 写入 `benchmark_samples`、`sample_oracles`
- 输出导入结果和错误报告

样本导入器不负责：

- 输出标准化 bundle；这一步由 `scripts/datasets/normalize_samples.py` 负责
- 维护 `dataset_metadata/` 下的版本化元数据
- 创建或更新字典表与 `risk_subtype_display_meta`
- 创建 run
- 启动环境
- 调用 Agent
- 生成报告

worker 运行链会在样本执行完成后消费 `sample_oracles`，写入 `oracle_results` 并生成 `execution_summaries`。这属于运行时评测职责，不属于导入职责。
