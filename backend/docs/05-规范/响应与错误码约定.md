# 响应与错误码约定

本文档是后端统一响应包裹和稳定错误码的主维护文档。

当前统一 envelope 的实现入口为：

- `app.shared.http`
- `app.shared.schemas`
- `app.shared.exception_handlers`

## 1. 成功响应包裹

业务成功统一使用：

```json
{
  "code": 0,
  "data": {},
  "message": "success"
}
```

约定：

- `code = 0` 表示成功
- `data` 可以是对象、数组、字符串、数字或 `null`
- `message` 默认使用 `success`

## 2. 业务失败响应包裹

业务失败优先使用：

```json
{
  "code": 1000,
  "data": null,
  "message": "错误描述"
}
```

当前实现中：

- 使用 `app.shared.errors` 中的 `DomainError` 及其子类抛出的业务错误会返回 `{ code, data, message }`
- `RequestValidationError` 会被统一转换为 envelope，字段错误明细放在 `data.errors`
- 纯 `HTTPException` 会被兜底转换为 `{ code: http_status, data: null, message }`
- 根路径、`/api/`、`/api/v1/` 这类元信息接口也统一返回 envelope
- 当前公开接口不存在 `app/api/response.py` 兼容层；文档与实现统一以 `app.shared.http` 为准

## 3. 当前稳定错误码

以下错误码均为当前实现已返回且已验证的口径。

| code | HTTP | 状态 | 适用范围 | 含义 |
| --- | --- | --- | --- | --- |
| `0` | 200 | 已实现 | 全部接口 | 成功 |
| `1000` | 422 | 已实现 | 全部接口 | 通用参数校验失败 |
| `1001` | 401 | 已实现 | `POST /api/v1/auth/login` | 用户名或密码错误 |
| `1002` | 409 | 已实现 | `POST /api/v1/auth/register` | 用户名或邮箱已被注册 |
| `1003` | 409 | 已实现 | `PUT /api/v1/user/profile` | 用户名已被占用 |
| `1004` | 403 | 已实现 | `PUT /api/v1/user/profile` | 邮箱不可修改 |
| `500` | 500 | 已实现 | `POST /api/v1/user/avatar` 等通用兜底 | 服务内部错误 |
| `40002` | 400 | 已实现 | `precheck` / `submit` | 参数校验失败 |
| `40100` | 401 | 已实现 | 需要登录的业务接口 | 未登录或登录失效 |
| `40300` | 403 | 已实现 | 评测详情 / 动作接口 | 无权访问他人任务 |
| `40400` | 404 | 已实现 | 数据集详情 / 评测详情 | 目标不存在 |
| `40901` | 409 | 已实现 | 动作接口 | 当前状态不允许该动作 |
| `40902` | 409 | 已实现 | 动作接口 | 已达到暂停次数上限 |
| `50000` | 500 | 已实现 | `datasets` / `agents` / `evaluations` | 服务内部错误 |

## 4. 鉴权失败口径

当前公共依赖 `get_current_user` 的失败口径如下：

- 未携带 Bearer token：`40100`，消息为 `未登录或登录已失效。`
- token 无效或过期：`40100`，消息为 `未登录或登录已失效。`
- token 解析成功但用户不存在：`40100`，消息为 `未登录或登录已失效。`

## 5. 参数校验失败示例

```json
{
  "code": 1000,
  "data": {
    "errors": [
      {
        "field": "email",
        "reason": "value is not a valid email address"
      }
    ]
  },
  "message": "请求参数校验失败"
}
```
