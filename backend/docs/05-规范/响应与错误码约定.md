# 响应与错误码约定

本文档是后端统一响应包裹和稳定错误码的主维护文档。

## 1. 成功响应包裹

业务成功统一使用：

```json
{
  "code": 0,
  "data": {},
  "message": "success"
}
```

约定：

- `code = 0` 表示成功
- `data` 可以是对象、数组、字符串、数字或 `null`
- `message` 默认使用 `success`

## 2. 业务失败响应包裹

业务失败优先使用：

```json
{
  "code": 1000,
  "data": null,
  "message": "错误描述"
}
```

当前实现中：

- 使用 `fail()` / `unauthorized()` 抛出的业务错误会返回 `{ code, data, message }`
- 纯 `HTTPException` 会被兜底转换为 `{ code: http_status, data: null, message }`

## 3. 当前稳定错误码

以下错误码分为两类：

- 已实现：当前后端代码已经返回
- 已冻结待实现：当前 `share/` 契约已经固定，后续接口实现应沿用

| code | HTTP | 状态 | 适用范围 | 含义 |
| --- | --- | --- | --- | --- |
| `0` | 200 | 已实现 | 全部接口 | 成功 |
| `1000` | 400 | 已实现 | `auth` / `user` | 通用业务参数错误 |
| `1001` | 401 | 已实现 | `POST /api/v1/auth/login` | 用户名或密码错误 |
| `1002` | 409 | 已实现 | `POST /api/v1/auth/register` | 用户名或邮箱已被注册 |
| `1003` | 409 | 已实现 | `PUT /api/v1/user/profile` | 用户名已被占用 |
| `1004` | 403 | 已实现 | `PUT /api/v1/user/profile` | 邮箱不可修改 |
| `401` | 401 | 已实现 | 需要鉴权的已实现接口 | 未授权或 token 无效 |
| `500` | 500 | 已实现 | `POST /api/v1/user/avatar` 等通用兜底 | 服务内部错误 |
| `40002` | 400 | 已冻结待实现 | `precheck` / `submit` | 参数校验失败 |
| `40100` | 401 | 已冻结待实现 | 需要登录的规划中接口 | 未登录或登录失效 |
| `40300` | 403 | 已冻结待实现 | 评测详情 / 动作接口 | 无权访问他人任务 |
| `40400` | 404 | 已冻结待实现 | 数据集详情 / 评测详情 | 目标不存在 |
| `40901` | 409 | 已冻结待实现 | 动作接口 | 当前状态不允许该动作 |
| `40902` | 409 | 已冻结待实现 | 动作接口 | 已达到暂停次数上限 |
| `50000` | 500 | 已冻结待实现 | 规划中公共接口 | 服务内部错误 |

## 4. 鉴权失败口径

当前公共依赖 `get_current_user` 的失败口径如下：

- 未携带 Bearer token：`401`，消息为 `未授权，请先登录`
- token 无效或过期：`401`，消息为 `token 无效或已过期`
- token 解析成功但用户不存在：`401`，消息为 `token 无效或已过期`

- 接口级请求/响应示例：主维护在 `share/`
